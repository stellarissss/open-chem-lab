# 美术资产链调研

> 核实日期：2026-11-14 · 触发：用户指定 `tikz-chemlab`（需转换）与 `@itkdm/open-lab-components`，并授权「找更好的」。
> 方法：GitHub API 目录树枚举 + npm registry + CTAN / GitHub / npm 官方原文打开 + LPPL 1.3c 条款原文。
> 结论：**两个点名项目都可用，但各有一个必须处理的许可证陷阱**；同时找到互补的更优组合。

### 许可证陷阱与解法（关键，已查 LPPL 1.3c 原文）

LPPL 1.3c 的关键条款：

- **Clause 1**：`Activities other than distribution and/or modification of the Work are not covered by this license; they are outside its scope. In particular, the act of running the Work is not restricted and no requirements are made concerning any offers of support for the Work.`
  → **运行宏包（编译）不受限制，对产物不作要求**。用 `\tkzBeaker` 编译出的 PDF/SVG 图是「运行输出物」，不是 Work 也不是 Derived Work，**可用于本产品，且不受 Apache-2.0 与 LPPL 冲突影响**（我们不分发宏包源码）。
- **Clause 6**（若修改源码再分发）：要求 (a) 明确标识为修改版；(b) 每个组件附变更说明或完整变更日志；(c) 不得暗示原作者提供支持；(d) 随附完整未修改原作或足以获取它的信息。**改名 + 附原件 + 变更日志**。
- **Clause 3 / 7**：分发 Compiled Work（由 Work 编译出的可安装形式）须满足接收者可同样安装；**针对的是宏包本身的编译产物，不是用户用宏包画的图**。
- **Clause 9**：以其他格式分发 Work 不解除义务 —— 提醒「把 `.tex` 整体翻译成 JS 组件再分发」仍受约束。

**因此确定策略（写进 ADR-0004）**：
1. **只转译编译输出物**（`.tex` 源文件 → `standalone` PDF → SVG → React 组件），产物是原创的图形资产表示。
2. **不 fork、不修改、不随产品分发宏包源码**；转换脚本只在**构建期**从 CTAN/上游拉取源码，产出物进 `assets/`，源码不进仓库。
3. 在 `CREDITS.md` 与 `assets/attribution/` 署名 aihua + pst-labo 四位原作者，注明 LPPL-1.3c 与「输出物」。
4. 若未来确需改宏包（例如增加器材），则按 Clause 6 改名、附变更日志、附原始副本，并单独开一个 `upstream/` 目录，**不与主产品代码混同**。
5. 商业化前就「LPPL 输出物商用」做一次法务确认（工程判断，非法律意见）。

## 二、点名项目 2：@itkdm/open-lab-components

| 项 | 核实结果 |
|---|---|
| 仓库 | [`itkdm/open-lab-components`](https://github.com/itkdm/open-lab-components) ★10 · MIT · npm `@itkdm/open-lab-components` v0.1.1 · Node ≥18 · 演示站 `olc.itkdm.com` |
| 定位 | 「面向宿主系统与 AI 客户端的 STEM 教学组件基础设施」；`components/` 是单一事实源，派生 registry / JS API / 静态站 / **MCP Server** |
| 规模 | **213+ 组件 / 41 分类** / zh-CN + en |
| 交付形式 | 零依赖 **HTML fragment**（`data-cmp-id` + CSS 变量如 `--cmp-size` / `--cmp-body`）、JS API（`lab.list/get/categories/readSync/mount/unmount/updateProps`）、Registry JSON、静态站、MCP tools/prompts/resources |

### 化学相关 37 个组件（GitHub API 目录树枚举，实测）

| 分类 | 数量 | 组件 ID 示例 |
|---|---|---|
| `chemistry/labware` | **26** | `beaker.graduated` / `test-tube` / `test-tube-rack` / `bunsen-burner` / `alcohol-lamp` / `burette` / `condenser` / `crucible` / `distillation-flask` / `dropper` / `erlenmeyer-flask` / `evaporating-dish` / `funnel` / `gas-jar` / `glass-rod` / `graduated-cylinder` / `narrow-mouth-bottle` / `round-bottom-flask` / `separating-funnel` / `spatula` / `stand` / `tripod` / `wash-bottle` / `wide-mouth-bottle` / `wire-gauze` / `ph-beaker`（indicator） |
| `chemistry/reaction` | **5** | `acid-base.interactive` / `electrolysis.interactive` / `equilibrium.interactive` / `rate.interactive` / `redox.interactive` |
| `chemistry/model` | **3** | `bonding.interactive` / `molecule.ball-stick` / `periodic-table.interactive` |
| `chemistry/gas` | 1 | `ideal-gas-law.interactive` |
| `chemistry/solution` | 1 | `concentration.interactive` |

**价值判断**：`chemistry/labware` 26 件器材与 tikz-chemlab 的 13 个宏**高度互补** —— open-lab-components 提供的是**可直接挂载、带 CSS 变量、可 `updateProps` 动态改状态**的 HTML 组件；tikz-chemlab 提供的是**出版级、参数化的组合装置**（滴定/蒸馏/回流）。而 5 个 `*.interactive` 组件（酸碱/电解/平衡/速率/氧化还原）正好对应 NB 的「速率/平衡/压强三大系统」教学交互，可直接作为教具层原型。

**陷阱与解法**：
- v0.1.1、★10、2026-10 才活跃 → **早期项目**，须固定版本 + `npm run validate` 回归测试；不把它当不可变依赖。
- 它是 **HTML fragment + CSS 变量**，不是原生 React 组件。集成方式：用 `lab.mount(html, container, props)` 在 React 的 `useEffect` 中挂载到一个 `ref` 容器，状态变更用 `lab.updateProps`；或写一个薄 `<LabComponent id ... />` 包装层（约 30 行）。**不要把 213 个 fragment 手工改成 JSX**。
- 「MCP Server 集成」是其特色，但本项目不依赖 MCP 才能运行；可作为 M4 让 AI 助教推荐实验组件的可选增强。

### 关键缺口：CC0 化学器材 3D 模型稀缺

多引擎检索（Kenney / Quaternius / Poly Haven / Sketchfab / BlendSwap / CGTrader）结果：3D 玻璃器皿几乎全部来自 **TurboSquid / CGTrader / Sketchfab / RenderHub / BlendKit** 等商业或逐模型授权站点，没有可直接批量集成、许可清晰的 CC0 化学器材 GLB 包。`Poly-Haven/Public-Assets` 与 `KenneyNL/kenney-assets` 的 GitHub 路径均 404（前者无官方仓库，后者在官网发资产）。

**解法（ADR-0007）**：3D 器材**程序化生成** —— 用 Three.js `LatheGeometry`（旋转体：烧杯/试管/锥形瓶/圆底烧瓶/量筒）、`TubeGeometry`（导管/冷凝管）、`CylinderGeometry`（铁架台/本生灯）+ 玻璃材质 + 由 2D SVG 轮廓 `ExtrudeGeometry`。好处：
- 零外部资产依赖、无许可证风险；
- 与 2D SVG 共用同一套「器材参数表」（容量、口径、刻度、液位），2D/3D 一致；
- 液位/颜色/倾斜可直接由仿真状态驱动，天然支持动画。

## 五、转换可行性结论

| 步骤 | 工具 | 可行性 | 风险 |
|---|---|---|---|
| `.tex` → standalone PDF | `pdflatex` / `lualatex` / `tectonic`（宏包明确支持） | 已确认 | 需 TeX 环境（用 `texlive` Docker 镜像） |
| PDF → SVG | `dvisvgm --pdf`（TeX Live 自带，对 TikZ/字体支持最好）/ `pdf2svg` / `pdftocairo -svg` / Inkscape CLI | 成熟工具链（**判断**，M0 实测） | 字体需转路径或嵌入；渐变/图案可能需后处理 |
| SVG → 可动态组件 | SVGO 优化 → 拆出「液体层」为独立 `<path>` → 用 CSS 变量/`clipPath` 驱动液位与颜色 | 判断，M0 验证 | TikZ 输出可能把液体与玻璃合并为单路径，需拆层 |
| HTML fragment → React | `lab.mount` + 包装组件 | 已确认（README 提供 API） | 生命周期与 StrictMode 双挂载需处理 |

> 具体命令、目录与脚本见 [美术资产管线设计](../design/04-美术资产管线.md)。

## 六、逐资产署名清单要求（合规落地）

`assets/attribution/` 下每个资产（或资产组）一条记录，字段：

```
asset_id | 源项目 | 源 URL | 作者/机构 | 许可证 | 是否修改 | 署名文本 | 用于何处
```

必须覆盖：tikz-chemlab（含 pst-labo 四作者）、open-lab-components、LabIcons（Manon Zuurmond）、bioicons 每个图标（含 Servier / DBCLS 原始作者）、Lucide、Kenney 资产包、3Dmol.js 论文引用。CC-BY 与 CC-BY-SA 资产在产品 About 页与图注中可见。
