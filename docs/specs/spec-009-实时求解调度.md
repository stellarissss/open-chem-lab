# spec-009 · 实时求解调度

## 目标

M2 第二片：把 008 的「操作后求解一次」升级为**状态驱动实时求解**——容器状态变化即触发重算，稳态冻结省算力，焦点配额保证 60fps，并落地加热操作与温度轴实时演化。

## 范围

**做**：
- **自适应调度器**（`packages/scheduler/` 或 gateway 内，遵循 `01` §六包结构，落点开工前确认）：状态变化驱动重算、稳态冻结与缓存复用、关注度分数（视野内 + 刚被操作 + 有可见现象 + 用户聚焦）、16.7ms 帧预算动态配额。
- **表现层 60fps 插值**：求解结果与帧率彻底解耦，低分容器降频/冻结、焦点内诚实求解。
- **加热操作**：酒精灯/加热板器材（复用 apparatus 卡 + tikz-chemlab 资产），邻近交互范式进入加热态；温度随时间演化（真实热容/功率，不写死 ΔT），容器状态与现象的 `temperature_change` 指令实时派生。
- **温度轴**：选中容器的温度实时读数与演化曲线（表现层，数值来自求解/热模型）。

**不做**：称量配液/逐滴/测温计（→ 010）；固定气液装置、危险后果写实化、新化学体系（→ 011）；改事实层已签核数值。

## 验收标准（大略，正式稿细化）

1. 操作后容器状态变化在帧预算内触发重算，焦点内诚实求解、帧率恒 ≥ 60fps，焦点外算力随关注度单调下降。
2. 稳态容器命中缓存（内容寻址键，见 `01` §5.2），不重复求解；状态变化后正确失效。
3. 加热时温度按热容/功率演化、无写死 ΔT；温度现象由状态派生、三态出口如实。
4. 新增体系无需改调度代码；调度器可被独立替换（与求解/表现解耦）。
5. 既有门禁全绿、无回归；新调度逻辑有可判定单测。

## 技术要点

遵循 `01-Architecture.md`：§四自适应调度（关注度分数/帧预算）、§5.2 内容寻址缓存、§7.1 诚实计算（禁写死 ΔT）。复用 008 的 `container_state` 定向通道、`bench_world` 台面状态、现象渲染管线、托里拆利操作物理的干净分层。调度器落点与加热热模型来源开工前逐一向用户确认（L1）。
