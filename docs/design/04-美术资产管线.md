# 04 · 美术资产管线

> 目标：把用户指定的 `tikz-chemlab`（LPPL，需转换）与 `@itkdm/open-lab-components`（MIT）转成产品可用的 2D/3D 资产，**全程不重复造轮子、不踩许可证红线**。
> 依据：`research/03-美术资产链.md`、ADR-0004（LPPL 输出物）、ADR-0007（程序化 3D）。
> 状态：**设计为「待 M0 验证」**，命令与目录均已具体到可执行，但本阶段不实际跑构建（属 M0/M1）。

## 二、管线 A：open-lab-components → React 组件（零转换成本）

它本身就是零依赖 HTML fragment + JS API，**不需要构建转换**，只写一个薄包装层：

```tsx
// packages/web-ui/src/components/LabComponent.tsx（约 30 行，示意）
import { useEffect, useRef } from 'react';
import * as lab from '@itkdm/open-lab-components';

export function LabComponent({ id, props, style }: {
  id: string; props?: Record<string, unknown>; style?: React.CSSProperties;
}) {
  const ref = useRef<HTMLDivElement>(null);
  useEffect(() => {
    if (!ref.current) return;
    const html = lab.readSync(id);
    lab.mount(html, ref.current, props ?? {});
    return () => lab.unmount(ref.current!);
  }, [id]);                       // props 单独走 updateProps，避免重复挂载
  useEffect(() => {
    if (ref.current && props) lab.updateProps(ref.current, props);
  }, [props]);
  return <div ref={ref} className="cmp" data-cmp-id={id} style={style} />;
}
```

**注意事项（预料中的问题）**：
- React 18 StrictMode 会双调用 effect → 必须 `unmount` 清理干净，否则组件 DOM 重复。
- 组件通过 CSS 变量（`--cmp-size` / `--cmp-body` / `--cmp-liquid`）控制外观 → 我们把「仿真状态（液位、颜色、温度）」映射到这些变量，实现动态器材，无需重绘 SVG。
- 固定 npm 版本（`0.1.1`），CI 跑其 `npm run validate` 的等价检查；不把 `registry/*.json` 当手写数据。
- `chemistry/reaction` 的 5 个 `*.interactive` 组件可直接作为教具层原型（对应 NB 三大系统）。

## 三、管线 B：tikz-chemlab → 分层 SVG（核心转换）

### 3.1 合规边界（ADR-0004，先于技术）

```
构建期（Docker 内）：从 CTAN 拉取 tikz-chemlab 源码（.sty/.tex/Obj.tex）
   → 用 standalone 文档类编译成 PDF
   → PDF 转 SVG
   → 只把 SVG 产物写入 assets/labware/
   → 宏包源码不进仓库、不随产品分发
仓库内：只保留「生成脚本 + 器材参数表 + SVG 产物 + 署名」
```

依据 LPPL 1.3c **Clause 1**：「the act of running the Work is not restricted and no requirements are made concerning any offers of support」→ 编译输出物不受 LPPL 分发条款约束。若将来要**修改宏包源码再分发**，则触发 Clause 6（改名 + 变更日志 + 附原始未修改副本），必须单独 `upstream/` 目录隔离。

### 3.2 构建镜像与命令（待 M0 验证）

```dockerfile
# tools/asset-pipeline/Dockerfile（示意）
FROM texlive/texlive:latest
RUN apt-get update && apt-get install -y --no-install-recommends \
      dvisvgm pdf2svg poppler-utils inkscape && rm -rf /var/lib/apt/lists/*
# npm i -g svgo 用于产物优化
```

```bash
# tools/asset-pipeline/build-tikz.sh（示意，逐器材生成）
set -euo pipefail
MACROS=(TestTube HeatTube RoundFlask HeatFlask Funnel GraduatedCylinder \
        Pipette LargePipette Titration Distillation SeparatoryFunnel Stand Column)
for m in "${MACROS[@]}"; do
  cat > "build/\\tkz${m}.tex" <<TEX
\\documentclass[tikz,border=2pt]{standalone}
\\usepackage{tikz-chemlab}
\\begin{document}
\\begin{tikzpicture}[scale=1.2]
  \\tkz${m}
\\end{tikzpicture}
\\end{document}
TEX
  # 方案①（推荐）：DVI 路线，dvisvgm 对 TikZ/字体支持最好
  lualatex --output-format=dvi "build/\\tkz${m}.tex"
  dvisvgm --pdf --font-format=woff --exact "build/\\tkz${m}.dvi" \
          -o "assets/labware/\\tkz${m}.svg"
  # 方案②（备选）：PDF 路线
  # pdflatex "build/\\tkz${m}.tex" && pdf2svg "build/\\tkz${m}.pdf" "assets/labware/\\tkz${m}.svg"
  svgo --multipass "assets/labware/\\tkz${m}.svg"
done
```

**参数化批量生成**：利用宏包选项一次生成变体（液位 `liquidLevel1=0/25/50/75/100`、液体颜色 `liquidStyle`、倾斜 `tiltAngle`、塞子 `stopper`、滴定管 `buretteLevel`、`TapOpen`），产出 SVG 序列，支撑液位动画与不同试剂外观。

### 3.3 转换后的技术处理（预料中的问题与预案）

| 问题 | 预案 |
|---|---|
| TikZ 输出把「玻璃」与「液体」画在同一路径，无法单独改液位 | ① 用 `standalone` + 分层 `scope` 生成两个 SVG 再合成；② 用 `liquidLevel=0` 与 `=100` 两张 SVG 做差集，程序化提取液体层；③ 最终兜底：把液位做成 `clipPath` 遮罩，只用一张玻璃 SVG（**推荐，最简单**） |
| 字体被转成 `<text>` 依赖本机字体 | `dvisvgm --font-format=woff` 嵌入，或 Inkscape `--export-text-to-path` 转曲 |
| 渐变/图案（`shadings`/`patterns`）在 SVG 中丢失 | 后处理用 CSS 渐变替换；或在产品侧用材质层覆盖 |
| SVG 体积大、含编辑器元数据 | `svgo --multipass`；移除 `sodipodi`/`inkscape` 命名空间 |
| `scale` 与坐标系不一致 | 统一 `viewBox`，在器材参数表里记录 `baselineY` 与 `mouthY`（液面/瓶口的 y 坐标），供引擎定位 |
| 颜色是硬编码 TikZ 色 | 生成后把关键 `fill`/`stroke` 替换为 CSS 变量 `var(--glass)` / `var(--liquid)` |

### 3.4 动态化：一张 SVG + 三个变量

```tsx
// 液位用 clipPath，颜色用 CSS 变量，倾斜用 transform —— 不为每个状态生成一张图
<BeakerSvg
  style={{
    '--liquid': material.color,
    '--liquid-level': `${(volume / capacity) * 100}%`,
    transform: `rotate(${tilt}deg)`
  } as React.CSSProperties}
/>
```

> 这样 tikz-chemlab 的「参数化」优势保留在**构建期**（生成不同器材/装置），运行期动态性由 CSS/clipPath 承担，避免资产数量爆炸。

## 四、管线 F：程序化 3D 器材（无外部模型）

| 器材 | Three.js 几何 | 参数来源 |
|---|---|---|
| 烧杯 / 量筒 / 试管 / 锥形瓶 / 圆底烧瓶 | `LatheGeometry`（由 SVG 轮廓采样成 profile 点集） | `apparatus.profile` |
| 导管 / 冷凝管 / 铁架台杆 | `TubeGeometry` / `CylinderGeometry` | 参数表 |
| 漏斗 / 蒸发皿 / 坩埚 | `LatheGeometry` / `LatheGeometry` | 参数表 |
| 玻璃材质 | `MeshPhysicalMaterial`（transmission / roughness / ior 1.47） | 统一玻璃材质预设 |
| 液体 | 由 `LatheGeometry` 截取 + `clipPath` 等价的裁剪面，随 `volume` 变化 | 仿真状态 |

**优势**：与 2D 共用 `apparatus` 参数表 → 2D/3D 一致；液位/颜色/倾斜直接由仿真状态驱动；零外部资产、零许可证风险；可导出 glTF 供社区复用。
