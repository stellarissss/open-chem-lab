# 04 · 美术资产管线（出版级写实 2D）

> 目标：把 `tikz-chemlab`（LPPL，需转换）与 `@itkdm/open-lab-components`（MIT）转成产品可用的**写实 2D 实验台器材**，全程不重复造轮子、不踩许可证红线。
> 依据：台账 5.3 / 6.3（C19 销项）、`research/03`、ADR-0004（LPPL 输出物）、ADR-0007（2D 写实实验台 + 分子级 3D）。
> **v2.0**：初版「双层皮肤可切换 / 程序化 3D 器材 / `assets/structure/`」已作废；主调固定为**出版级写实 2D**，3D 只做分子 / 晶体。

---

## 一、资产分层与来源决策

| 层 | 来源 | 产出 | 许可证处理 |
|---|---|---|---|
| A · **主资产**（写实器材与组合装置） | **`tikz-chemlab` 13 宏 → SVG** | 分层 SVG + 液位控制 | **LPPL 输出物**（只转译编译结果，不改宏包源码） |
| B · 辅助器材 / 交互组件 | `@itkdm/open-lab-components` 化学相关组件 | HTML fragment → React 包装（薄层） | MIT，保留版权声明；**与写实主调不冲突时才用** |
| C · UI 图标 | Lucide (ISC) / Tabler (MIT) | React 图标组件 | 保留声明 |
| D · 科学插画 / 图鉴配图 | LabIcons (CC-BY-4.0)、bioicons（逐个许可） | SVG 配图 | **逐资产署名** |
| E · 结构式 / 分子 3D | SmilesDrawer、Kekule.js、RDKit.js、**3Dmol.js** | 运行时生成 SVG / 3D | 无需静态资产 |
| F · **3D 范围** | **只做分子 / 晶体 / 球棍模型**（3Dmol.js） | 运行时 3D 视图 | BSD-3（M0 复核）+ 论文引用 |
| G · 音效 / 粒子贴图 | Kenney (CC0，待复核) / WebAudio 合成 | 音频与纹理 | 待 M0 复核包内 LICENSE；**卡通 2D/3D 器材不入库** |

**关键结论**：台账 6.3 定「2D 写实为主、3D 只做分子」后，早期「CC0 化学器材 3D 模型稀缺 → Three.js 程序化建模」的整套工作**降级为可选长线、不进 M1**；`extract-profile.mjs`、`assets/labware-profiles/`、`packages/viewer-3d/` 的器材几何部分移出主流程。

## 二、管线 B：open-lab-components → React 组件（辅资产，零转换成本）

它本身是零依赖 HTML fragment + JS API，不需要构建转换，只写一个薄包装层：

```tsx
// packages/lab-components/src/LabComponent.tsx（约 30 行，示意）
import { useEffect, useRef } from 'react';
import * as lab from '@itkdm/open-lab-components';

export function LabComponent({ id, props, style }: {
  id: string; props?: Record<string, unknown>; style?: React.CSSProperties;
}) {
  const ref = useRef<HTMLDivElement>(null);
  useEffect(() => {
    if (!ref.current) return;
    const html = lab.readSync(id);
    lab.mount(html, ref.current, props ?? {});
    return () => lab.unmount(ref.current!);
  }, [id]);                       // props 单独走 updateProps，避免重复挂载
  useEffect(() => {
    if (ref.current && props) lab.updateProps(ref.current, props);
  }, [props]);
  return <div ref={ref} className="cmp" data-cmp-id={id} style={style} />;
}
```

**注意事项**：

- React 18 StrictMode 会双调用 effect → 必须 `unmount` 清理干净，否则 DOM 重复。
- 组件通过 CSS 变量（`--cmp-size` / `--cmp-body` / `--cmp-liquid`）控制外观 → 把仿真状态（液位、颜色）映射到这些变量，无需重绘 SVG。
- 固定 npm 版本（`0.1.1`），CI 跑其 `npm run validate` 的等价检查；不把 `registry/*.json` 当手写数据。
- **写实一致性复核**：辅助资产的扁平风格若与出版级写实主调冲突，则不用该组件，改由 tikz-chemlab 输出物覆盖。

## 三、管线 A：tikz-chemlab → 分层 SVG（主资产，核心转换）

### 3.1 合规边界（ADR-0004，先于技术）

```
构建期（Docker 内）：从 CTAN 拉取 tikz-chemlab 源码（.sty/.tex/Obj.tex）
   → 用 standalone 文档类编译成 PDF
   → PDF 转 SVG
   → 只把 SVG 产物写入 assets/labware/
   → 宏包源码不进仓库、不随产品分发
仓库内：只保留「生成脚本 + 器材参数表 + SVG 产物 + 署名」
```

依据 LPPL 1.3c **Clause 1**：「the act of running the Work is not restricted and no requirements are made concerning any offers of support」→ 编译输出物不受 LPPL 分发条款约束。若将来要**修改宏包源码再分发**，则触发 Clause 6（改名 + 变更日志 + 附原始未修改副本），必须单独 `upstream/` 目录隔离并新增 ADR。

### 3.2 构建镜像与命令（待 M0 验证）

```dockerfile
# tools/asset-pipeline/Dockerfile（示意）
FROM texlive/texlive:latest
RUN apt-get update && apt-get install -y --no-install-recommends \
      dvisvgm pdf2svg poppler-utils inkscape && rm -rf /var/lib/apt/lists/*
# npm i -g svgo 用于产物优化
```

```bash
# tools/asset-pipeline/build-tikz.sh（示意，逐器材生成）
set -euo pipefail
MACROS=(TestTube HeatTube RoundFlask HeatFlask Funnel GraduatedCylinder \
        Pipette LargePipette Titration Distillation SeparatoryFunnel Stand Column)
for m in "${MACROS[@]}"; do
  cat > "build/\\tkz${m}.tex" <<TEX
\\documentclass[tikz,border=2pt]{standalone}
\\usepackage{tikz-chemlab}
\\begin{document}
\\begin{tikzpicture}[scale=1.2]
  \\tkz${m}
\\end{tikzpicture}
\\end{document}
TEX
  # 方案①（推荐）：DVI 路线，dvisvgm 对 TikZ/字体支持最好
  lualatex --output-format=dvi "build/\\tkz${m}.tex"
  dvisvgm --pdf --font-format=woff --exact "build/\\tkz${m}.dvi" \
          -o "assets/labware/\\tkz${m}.svg"
  # 方案②（备选）：PDF 路线
  # pdflatex "build/\\tkz${m}.tex" && pdf2svg "build/\\tkz${m}.pdf" "assets/labware/\\tkz${m}.svg"
  svgo --multipass "assets/labware/\\tkz${m}.svg"
done
```

**参数化批量生成**：利用宏包选项一次生成变体（液位 `liquidLevel1=0/25/50/75/100`、液体颜色 `liquidStyle`、倾斜 `tiltAngle`、塞子 `stopper`、滴定管 `buretteLevel`、`TapOpen`），产出 SVG 序列，支撑液位动画与不同试剂外观。

### 3.3 转换后的技术处理（预料中的问题与预案）

| 问题 | 预案 |
|---|---|
| TikZ 输出把「玻璃」与「液体」画在同一路径，无法单独改液位 | ① 用 `standalone` + 分层 `scope` 生成两个 SVG 再合成；② 用 `liquidLevel=0` 与 `=100` 两张 SVG 做差集，程序化提取液体层；③ 最终兜底：把液位做成 `clipPath` 遮罩，只用一张玻璃 SVG（**推荐，最简单**） |
| 字体被转成 `<text>` 依赖本机字体 | `dvisvgm --font-format=woff` 嵌入，或 Inkscape `--export-text-to-path` 转曲 |
| 渐变 / 图案（`shadings`/`patterns`）在 SVG 中丢失 | 后处理用 CSS 渐变替换；或在产品侧用材质层覆盖 |
| SVG 体积大、含编辑器元数据 | `svgo --multipass`；移除 `sodipodi` / `inkscape` 命名空间 |
| `scale` 与坐标系不一致 | 统一 `viewBox`，在器材参数表里记录 `baselineY` 与 `mouthY`（液面 / 瓶口的 y 坐标），供实验台定位 |
| 颜色是硬编码 TikZ 色 | 生成后把关键 `fill` / `stroke` 替换为 CSS 变量 `var(--glass)` / `var(--liquid)` |

### 3.4 动态化：一张 SVG + 三个变量

```tsx
// 液位用 clipPath，颜色用 CSS 变量，倾斜用 transform —— 不为每个状态生成一张图
<BeakerSvg
  style={{
    '--liquid': material.color,
    '--liquid-level': `${(volume / capacity) * 100}%`,
    transform: `rotate(${tilt}deg)`
  } as React.CSSProperties}
/>
```

> tikz-chemlab 的「参数化」优势保留在**构建期**（生成不同器材 / 装置），运行期动态性由 CSS / clipPath 承担，避免资产数量爆炸。

## 四、管线 F：分子级 3D 视图（唯一 3D 用途）

| 需求 | 组件 | 输出 |
|---|---|---|
| 分子 / 晶体 / 球棍模型 | **3Dmol.js**（BSD-3，M0 复核） | WebGL 可缩放旋转的 3D 结构；支持 pdb / sdf / mol2 / xyz / cif |
| 结构式 2D | SmilesDrawer / Kekule.js / RDKit.js | 运行时生成 SVG |
| 微观视图 | 由 `solution_speciation` 驱动 | 分子 / 离子运动、键断裂与形成示意 |

- **官方要求引用 3Dmol.js 的 Bioinformatics 论文** → DOI 于 M0 补齐后写进 About 页与 `ASSETS.csv`。
- 备选：Mol* (MIT) / NGL Viewer (MIT)。
- **不做**：程序化 3D 器材、批量器材 GLB、轮廓点集提取、玻璃 `MeshPhysicalMaterial` 调优（长线，需单独 ADR）。
- 3D 场景只放分子 / 晶体，**不与容器内现象渲染抢 60fps 帧预算**（SP-1）。

## 七、验收标准（M0/M1）

| 检查 | 标准 |
|---|---|
| tikz 转换 | 13 个宏全部成功产出 SVG，`svgo` 后单文件 < 30 KB |
| 层级可拆 | 至少烧杯 / 试管 / 锥形瓶的液位可通过 `clipPath` 单独控制 |
| 字体 | 无外部字体依赖（`woff` 嵌入或已转曲） |
| **写实一致** | 主视觉为出版级写实 2D；无双层皮肤、无卡通器材、无程序化 3D 器材 |
| 组件集成 | 使用的 open-lab-components 组件在 React StrictMode 下挂载 / 卸载无重复 DOM |
| 参数表一致 | 同一 `apparatus` 参数表生成的 2D SVG 与容器容量 / 口径一致 |
| 署名 | 每个入库资产在 `ASSETS.csv` 有记录，CI 校验通过 |
| 源码隔离 | 仓库内**不含** tikz-chemlab 的 `.sty/.tex` 源文件 |
| 3D 范围 | 3D 仅用于分子 / 晶体 / 球棍模型；3Dmol.js 论文引用已登记 |
| 双平台 | 转换脚本在 Windows（WSL2/Docker Desktop）与 Linux 均可跑，LF 换行 |
| 许可证扫描 | CI 白名单通过（放行 LGPL-2.1/3.0，禁止 AGPL / GPLv2-only） |
