# 06 · 教学层设计

> 阶段：M3（沙盒跑通后叠加，符合 `CHARTER` D3「先做沙盒好玩」）。
> 对标：NB C6（教师端）、C7（学生端）、C2（教材同步）。
> 复用：ltijs (Apache-2.0)、xAPI Spec (Apache-2.0)、h5p-standalone (MIT)、VChemLab (MIT，数据结构参考)、open-lab-components 的 5 个 `chemistry/reaction/*.interactive` 组件。

## 一、设计原则

1. **不牺牲沙盒自由度**：教学层是「叠加在沙盒之上的模板与评估」，不是把玩法锁死成分步点击。同一实验，学生可自由探索，也可切换引导模式。
2. **不复制 NB 模板文案**：教材实验自行编写 + 参考开放教材与课标，标注来源（`CHARTER` 对标边界）。
3. **标准对接优先复用**：LTI 1.3 用 ltijs，学习行为上报遵循 xAPI，不自己发明协议。
4. **数据自主**：自托管，学习过程数据不出校；导出开放格式。

## 二、教学闭环（对标 NB「看—做—学—练—问—测」）

| 环节 | 功能 | 实现 |
|---|---|---|
| 看 | 步骤动画演示、微观过程慢放/定格 | 现象指令协议 + 时间轴重放；3Dmol.js 微观视图 |
| 做 | 引导式分步实验 / 自由沙盒 | `experiment_template` 驱动步骤；**任何步骤可跳过进入沙盒** |
| 学 | 知识点卡、反应图鉴、原理交互 | `content/experiments/` + 图鉴；复用 open-lab-components 的 `rate/equilibrium/acid-base/redox/electrolysis` 交互组件 |
| 练 | 配套练习、知识闯关、成就 | 题库 + 图鉴发现度；对标 NB C7 |
| 问 | 知识卡「为什么」+ 可选 AI 助教（M4） | 规则 `source` 与 `safety.real_life_warning` 自动生成解释 |
| 测 | 实验操作在线测评、过程数据可视化 | 操作事件流 → 评分规则 → 报告 |

## 三、教材同步实验模板

### 3.1 结构（`content/experiments/`）

```yaml
id: exp_jhs_oxygen_from_kmno4
title: 高锰酸钾分解制取氧气
curriculum:
  stage: 初中
  grade: 九年级
  textbooks: [人教版, 教科版, 苏教版, 沪科版]
  chapter: 我们周围的空气 / 氧气
  knowledge_points: [氧气的实验室制法, 催化剂, 分解反应]
steps:
  - {order: 1, action: "place", target: "app:test_tube", hint: "取一支干燥试管"}
  - {order: 2, action: "add", target: "sub:kmno4_s", amount_g: 5}
  - {order: 3, action: "assemble", target: "app:gas_collection", hint: "连接导管与集气瓶，检查气密性"}
  - {order: 4, action: "heat", target: "app:alcohol_lamp", duration_s: 30}
  - {order: 5, action: "collect", hint: "待气泡连续均匀冒出后收集"}
safety_checks:
  - {id: "s1", wrong_action: "先熄灭酒精灯再撤导管", consequence: "水倒吸导致试管炸裂", severity: high}
  - {id: "s2", wrong_action: "试管口朝人", consequence: "喷溅", severity: medium}
observable:
  expected_effects: ["spawn_particles:mat:O2", "bubbling"]
  curves: ["temperature", "mass"]
grading:
  - {criterion: "检查气密性", points: 20, event: "assemble:checked"}
  - {criterion: "收集时机正确", points: 20, event: "collect:after_stable_bubbles"}
  - {criterion: "撤管顺序正确", points: 30, event: "stop:before_remove_tube"}
report_template: "report_oxygen.md"
```

### 3.2 覆盖策略（判断，M3 校准）

- 优先覆盖**四个主流教材版本共有的核心实验**（约 60–80 个），再按版本差异补充。
- 每个模板必须绑定 `golden-cases/` 里的断言，CI 保证规则改动不破坏教材实验。
- 模板只描述**步骤、器材、目标现象、评分点**，不含任何商业产品文案。

## 四、分步指导与操作纠错

| 机制 | 说明 |
|---|---|
| 引导模式 | 高亮下一步器材、给出提示、允许「自由探索」随时切出 |
| 实时纠错 | 监听操作事件流，匹配 `safety_checks`；错误操作**照常产生后果**（不阻止），但弹出知识卡 + 慢放回放 |
| 后果解释 | 从规则的 `source` / `safety.real_life_warning` / `thermo` 自动生成「为什么会这样」 |
| 一键重置 | 回到步骤起点，零成本反复练 |
| 分级提示 | 提示 1（现象线索）→ 提示 2（器材线索）→ 提示 3（完整步骤），避免直接给答案 |

> **关键设计**：纠错**不阻止错误**，而是让错误后果可视化 —— 这正是 NB C4 最有价值的部分，也是 `CHARTER` 第 0 条「好玩」与「专业」的交汇点。

## 五、实验报告（对标 NB C7）

自动生成，导出 Markdown / PDF / CSV：

| 段落 | 数据来源 |
|---|---|
| 实验名称、时间、操作者 | 会话元数据 |
| 器材与试剂清单 | `apparatus` / `substance` 引用 |
| 操作时间轴 | `save.timeline` |
| 四条曲线（温度/pH/压强/质量） | 仿真采样 |
| 反应式与现象 | 命中的 `reaction_rule`（带 `source` / `confidence`） |
| 现象截图 | 关键帧导出 |
| 结论与误差讨论 | 模板 + 用户输入 |
| 安全提示 | `safety.real_life_warning` + 常驻免责声明 |

支持**多参数对比**（同一实验改浓度/温度，曲线叠加显示），对标 NB「支持对比不同参数下的实验结果」。

## 六、操作测评与过程数据

```
操作事件流 → 评分规则匹配 → 过程数据可视化
```

- 事件类型：`place / add / pour / heat / ignite / power / seal / stir / filter / measure / stop`。
- 评分维度：步骤正确性、顺序、参数精度、安全规范、耗时。
- 教师端看板：班级完成度、高频错误点、能力雷达、过程回放。
- **xAPI 语句**：`Actor(学生) + Verb(执行了) + Object(步骤) + Result(得分/耗时) + Context(实验/班级)` 写入 LRS（可自托管）。

## 七、教师端 / 学生端 / 班级

| 角色 | 功能 |
|---|---|
| 教师 | 授课演示（广播自己的实验画面）、布置探究作业、查看班级报告与过程数据、发布自定义实验模板、导出成绩 |
| 学生 | 预习/课中/课后、引导实验、自由沙盒、闯关与勋章、查看自己的报告与薄弱点 |
| 管理 | 本地账号、班级、角色权限、模板审核、数据导出与备份 |

> **GPL 隔离提醒**：H5P 核心库（`h5p-php-library`，GPL-3.0）与 PhET 单 HTML（GPL）若使用，只能是**独立自托管页面**，不 import、不合并进主构建产物（ADR-0005）。

## 九、正确性护栏（教学场景更严格）

1. 教学模板引用的规则必须是 `confidence: verified`。
2. 每条现象在界面标注「教学近似，非实验级数据」。
3. 现实高危操作常驻提示「现实操作勿模仿」。
4. 教材模板变更需内容审核 + 黄金用例回归。
5. 测评评分规则与操作步骤解耦，便于按教材版本替换。
