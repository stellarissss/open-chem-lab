# 02 · 仿真内核与玩法

> 依据：`CHARTER` D1 混合分层 / D3 先做沙盒好玩 / D4 规模。
> 关联 ADR：0002、0006（规则数据驱动）、0007（程序化 3D）。
> **本节的关键结论来自对 Sandspiel `crate/src/species.rs` 源码的实读**，不是推测。

## 一、现状：Sandspiel 能给我们什么，不能给什么

### 已核实的源码结构（2026-11-14 实读 `crate/src/species.rs`）

```rust
#[wasm_bindgen]
#[repr(u8)]
pub enum Species {
    Empty=0, Wall=1, Sand=2, Water=3, Gas=4, Cloner=5, Fire=6,
    Wood=7, Lava=8, Ice=9, Sink=10, Plant=11, Acid=12, Stone=13,
    Dust=14, Mite=15, Oil=16, Rocket=17, Fungus=18, Seed=19,
}

impl Species {
    pub fn update(&self, cell: Cell, api: SandApi) {
        match self {
            Species::Sand  => update_sand(cell, api),
            Species::Water => update_water(cell, api),
            /* …每种物质一个硬编码分支… */
        }
    }
}

// 反应逻辑 = 邻域采样 + 硬编码 if/else
pub fn update_lava(cell: Cell, mut api: SandApi) {
    let sample = api.get(dx, dy);
    if sample.species == Species::Water {
        api.set(0, 0, Cell { species: Species::Stone, .. }); // 岩浆遇水→石头
        api.set(dx, dy, EMPTY_CELL);
    }
}
```

- `Cell` 结构：`{ species: u8, ra: u8, rb: u8, clock: u8 }` —— 一个网格 4 字节，`ra/rb` 复用为寿命/染色/状态，`clock` 计时。
- `SandApi` 提供：`get(dx,dy)` / `set` / `get_fluid` / `set_fluid(Wind{dx,dy,pressure,density})` / `rand_dir` / `rand_vec` / `rand_int` / `once_in` / `get_fluid().pressure`。
- **流体风场**（`Wind`）是独立的第二张网格，已实现压强/密度/方向耦合 —— 这正好是 NB「压强系统」的物理底座。
- 渲染在 WebGL，流体代码来自 PavelDoGreat/WebGL-Fluid-Simulation（MIT）。
- README 明确其长期目标「platform to support editing and uploading of your own elements via a programmable cellular automata API」—— 与我们的方向一致，但**尚未实现**。

### 结论（决定二次开发方案）

| 能直接用 | 必须改造 |
|---|---|
| 网格数据结构、双缓冲、邻域 API、风场/压强、WebGL 渲染、WASM 构建链、`crate/Cargo.toml` | ① `Species` 硬编码枚举 → **数据驱动材质表**；② `match` 硬编码反应 → **规则表查询**；③ 无化学计量/浓度/温度/pH概念 → 扩展 cell 状态；④ 无器材/容器语义 → 增加 apparatus 层 |

> 这正是 ADR-0006 的依据：**不能把上万物质的反应硬编码进 Rust**，否则每加一个物质都要重编译 WASM，既不可维护也无法实现 D4。

## 二、L0 改造方案（数据驱动的落沙引擎）

### 2.1 材质表（Material Registry）

把 `enum Species` 换成运行时从规则包加载的 `MaterialTable`：

```rust
pub struct Material {
    pub id: u16,                 // 表现型材质 ID（≤512 种进入热路径）
    pub phase: Phase,            // Solid/Liquid/Gas/Plasma/Aqueous
    pub density: f32,            // 决定沉降/浮起
    pub color: [u8;4],
    pub thermal: Thermal,        // 比热、导热、燃点、沸点、熔点
    pub conductivity: f32,       // 导电性（电解/电路）
    pub reactivity_class: u16,   // 规则匹配的分类键（酸/碱/氧化剂/还原剂/…）
    pub flags: u32,              // 可倾倒/可点燃/可密封/有毒/放射性…
}
```

- `Cell` 扩展为 `{ material_id: u16, amount: u16, temp: i16, aux: u16 }`（8 字节），保留 60fps 可行性判断（M0 实测）。
- 全局更新循环用 `for material in table` 驱动，`update` 变为通用物理 + 查规则表，不再 `match` 每种物质。

### 2.2 反应查询（热路径零 RTT）

```
每帧对相邻 cell 对 (a,b) 计算 pair_key = (min(id), max(id), 条件桶)
   → 查本地编译规则包（哈希表 / 完美哈希） 
   → 命中：生成 CellTransform { from, to, coeff, effects[] }
   → 未命中：不做化学变换，只做物理运动（扩散/沉降/热传导）
```

- 条件桶把连续量（温度、浓度、pH、压强、催化剂）离散化，避免浮点规则爆炸。
- 规则包由服务端离线编译成二进制（Top-N 高频），启动时载入 WASM 线性内存，**断网可玩**。
- 化学计量：以 `amount` 做守恒，反应按系数消耗/生成，避免「无限产物质」。

### 2.3 物理系统（复用 Sandspiel + 扩展）

| 系统 | 来源 | 扩展 |
|---|---|---|
| 重力/沉降/堆叠 | Sandspiel `update_sand/water/oil` | 按 `density` 通用化 |
| 流体与风场压强 | Sandspiel `Wind` / WebGL-Fluid | 接入密闭容器压强累积 → 爆瓶阈值 |
| 热传导与相变 | Sandspiel fire/ice/lava | 接入 `thermal` 参数：熔点/沸点/燃点；放热/吸热由规则 `thermo` 驱动 |
| 扩散与浓度 | Sandspiel gas | 水溶液浓度梯度、指示剂变色 |
| 电流 | Sandspiel 无 | 新增：电极/导线连通性 → 电解、短路起火 |
| 光/催化 | 无 | M2 增强：光照、催化剂作为条件桶 |

## 三、现象系统（12 类，先做精不做多）

> 「好玩」由这 12 类现象 + 4 条曲线决定，比堆一万种物质更重要。每类是一个**可组合的渲染原语**，由规则 `effects` 编排。

| # | 现象 | 渲染实现 | 物理量 | 典型规则 |
|---|---|---|---|---|
| P1 | 变色 | `color_lerp` / 指示剂色阶 | pH | 酸碱中和、石蕊/酚酞 |
| P2 | 气泡/气体 | 生成 Gas 粒子 + 上浮 + 逸出 | 压强/物质的量 | 碳酸盐+酸、活泼金属+酸 |
| P3 | 沉淀 | 生成 Solid 粒子 + 沉降 + 浑浊度 | 溶度积近似 | 银离子+氯离子、钡离子+硫酸根 |
| P4 | 结晶 | 成核 + 晶格生长 shader | 温度/浓度 | 冷却热饱和溶液、硫酸铜 |
| P5 | 燃烧/火焰 | Fire 粒子 + 光晕 + 消耗氧气 | 温度/燃点 | 镁条、蜡烛、氢气 |
| P6 | 爆炸 | 压强脉冲 + 冲击波 + 碎片粒子 | 压强/能量 | 粉尘爆炸、氢气爆鸣、密闭加热 |
| P7 | 烟雾 | 半透明粒子 + 扩散 | 浓度 | 白磷、氨+氯化氢 |
| P8 | 腐蚀/溶解 | 材质逐层消去 + 表面噪声 | 浓度/时间 | 酸蚀金属/大理石 |
| P9 | 放热升温 | 温度场 + 曲线 + 蒸汽 | ΔH | 中和、浓硫酸稀释 |
| P10 | 吸热降温 | 温度场 + 曲线 + 结霜 | ΔH | 硝酸铵溶解 |
| P11 | 压强爆瓶 | 容器破裂动画 + 内容物喷射 | 压强 | 密闭加热、产气过快 |
| P12 | 电极析气 | 电极气泡 + 电流路径可视化 | 电流 | 电解水、电解饱和食盐水 |

**四条实时曲线**：温度 / pH / 压强 / 质量，横轴时间，支持多参数对比并自动进实验报告（对标 NB C7）。

## 四、双视图（一个仿真状态，两种呈现）

| 视图 | 交互 | 器材语义 | 目标 |
|---|---|---|---|
| **实验台模式** | 从器材栏拖拽摆位；倾倒、加热、点燃、通电、密封加压、搅拌、过滤、滴定、称量 | 完整（容量、刻度、口径、耐热、密封性、导管连接） | 对标 NB 的 DIY 器材玩法，教具主力 |
| **无限画布模式** | 直接喷洒表现材质，画墙、画火、画电极 | 无（纯粒子沙盒） | 对标落沙沙盒的爽感与涌现 |

**共享状态**：两种视图共用同一 `MaterialTable` 与规则包；实验台里的「烧杯」本质是一块带容器边界的网格区域，切换到画布视图时该区域展开为粒子。**这是「2D/3D 均可」的实现基础**：渲染层可换成 R3F 3D 表示，仿真状态不变。

### 器材逻辑（M1 最小集 20 件）

| 类 | 器材 | 关键参数 |
|---|---|---|
| 容器 | 烧杯、试管、锥形瓶、圆底烧瓶、量筒、集气瓶、蒸发皿、坩埚 | 容量 mL、刻度、口径、耐热上限、是否可密封 |
| 加热 | 酒精灯、本生灯、电热板、石棉网、三脚架 | 功率/温度、火焰高度 |
| 分离/计量 | 漏斗、分液漏斗、滴定管、移液管、玻璃棒、天平、药匙、滴管 | 流速、精度、活塞开闭 |
| 支撑/连接 | 铁架台+夹、导管、橡皮塞、冷凝管 | 连接拓扑（决定密闭与压强） |
| 电学 | 电源、电极、导线、开关 | 电压、极性、连通性 |
| 测量 | 温度计、pH 计、压强计 | 采样率、量程 |

> 器材参数表是**单一事实源**：同时驱动 2D SVG 渲染、3D 程序化建模（`LatheGeometry` 等）、容器容量计算与物理约束。见 `04-美术资产管线.md`。

## 五、招牌玩法：错误操作后果可视化（第一版就做）

| 场景 | 触发条件 | 连锁后果 | 教学点 |
|---|---|---|---|
| 加热密闭容器 | 密封 + 加热 + 液体/产气 | 压强↑ → 超过阈值 → 爆瓶 → 内容物喷射 | 气体压强、实验安全 |
| 浓硫酸稀释顺序反了 | 水倒入浓硫酸 | 剧烈放热 → 局部沸腾 → 飞溅 → 容器腐蚀 | 稀释操作规范、密度与放热 |
| 钠/钾入水 | 活泼金属 + 水（敞口） | 浮熔游响 → 燃烧 → 氢气爆鸣 | 金属活动性、密度、放热 |
| 试管口朝人加热 | 加热 + 试管口方向 | 暴沸喷溅 → 命中「人形靶」扣安全分 | 加热姿势 |
| 酒精灯对吹 / 用嘴吹灭 | 吹气 + 明火 | 火焰蔓延 → 起火 | 酒精灯使用规范 |
| 电路短路 | 导线直连电源两极 | 电流↑ → 升温 → 冒烟 → 起火 | 短路与电阻 |
| 白磷露置 | 白磷 + 空气 + 温度 | 自燃 → 白烟 | 着火点 |
| 高锰酸钾制氧先熄灯后撤管 | 加热制气 + 停止顺序错 | 水倒吸 → 试管炸裂 | 实验操作顺序 |

**反馈规范**：夸张但可解释；即时（< 200ms）；带音效、屏幕震动、慢放回放（1/4 速）、「为什么会这样」知识卡；一键重置。安全提示常驻。

## 六、元系统（自由度与长线）

| 系统 | 设计 |

| 自定义物质 | 编辑物性（密度/相态/颜色/热参数/反应分类）+ 写 SMARTS 规则；低置信标记「社区内容」 |
| 自定义器材参数 | 容量、口径、耐热、密封性可调 |

| 反应图鉴 / 发现度 | 每个已触发规则点亮一张卡（ reactants / 产物 / 条件 / 现象 / 来源 / 现实实验视频链接） |
| 成就与知识闯关 | 按知识点组织挑战（「只用 3 步制出氧气」），对标 NB C7 |
| 存档与分享 | 实验状态序列化（网格 + 器材布局 + 参数 + 时间轴）→ 一键分享链接；格式开放、可 diff |
| 实验报告 | 自动记录操作序列、四条曲线、现象截图、反应式、结论；导出 Markdown/PDF |
| 社区工坊（M4） | 订阅规则包/实验；Yjs CRDT 多人协作（自研，避开 tptmp AGPL） |

## 七、正确性护栏（贯穿全玩法）

1. 每条规则必须带 `source` 与 `confidence`（`verified` / `extracted` / `community` / `ml_guess`）。
2. **只有 `verified` 进实时沙盒主玩法**；`extracted` 需人工复核；`ml_guess` 只作图鉴/探索提示。
3. 未命中规则 → `{"fallback":"no_visible_change","hint":"试试加热或改变浓度"}` + 写未覆盖日志（数据飞轮）。
4. 界面常驻「教学近似，非实验级数据」「现实操作勿模仿」。
5. 规则变更有版本与回滚；CI 里跑「教材实验黄金用例集」，防止改规则把中和反应改错。
6. 不做「任意混合自动算产物」的承诺 —— 这是化学上的不可判定问题（`CHARTER` D4）。
