# 文档驱动开发流程（DocDD）· 阶段三起

> **状态**：生效（2026-11-20）。**决策依据**：台账 §10（P1–P6 + P2-补/P3-补/P5-补，逐字固定）。
> **适用范围**：阶段三 M1 起的**全部开发活动**。阶段二九步闭环（`docs/12`）是历史流程，保留不删、不追溯适用。
> **AI 入口**：根目录 [`AGENTS.md`](../AGENTS.md) 是上下文压缩后的恢复锚点；本文件是流程正文。

## 0. 总基调（最高优先级，先读这一段）

用户裁决（P2-补 / P3 / P5，**两次重复强调**）：

> 「我是个人开发者，项目开源非盈利且是娱乐性质，不用遵循太严格的企业标准。」

据此，本流程的全部设计服从一条主线：**轻量、务实、灵活，拒绝流程僵化**。DDD / spec-kit 的方法论是**参考 toolbox**，不是必须逐条照做的教条；任何规则若让开发变慢而没有实质收益，就按 P3-补的比例原则简化，并在留痕中说明。

三条不可动摇的底线（来自 CHARTER，不因「轻量」而放松）：

1. **数值零错**——化学事实层的方向、产物、计量、守恒、pH/浓度值必须准确。
2. **不重复造轮子**——动手前先搜开源成品与官方文档。
3. **不绕过 L2 裁决**——触及固定裁决/产品定义/许可证基线的变更，先问用户、先固定入台账。

## 1. 为什么不从零建流程（不重复造轮子）

本项目已有**企业级治理资产**，本流程是「显式化 + 轻量化 + 固化跨会话纪律」，不是另起炉灶：

| DDD / spec-kit 概念 | 本项目已有载体 | 本流程的动作 |
|---|---|---|
| constitution / Contract | `CHARTER.md` | 沿用，不新建 |
| 唯一事实源 / Specification 索引 | `docs/11-问题与决策台账.md` | 沿用，作为每个任务的裁决起点 |
| Technical 决策 | `docs/adr/`（ADR-0001…0010） | 沿用（L1 用 ADR） |
| 规格 / design | `docs/design/` 01–07 | 沿用，作为实现依据 |
| 实测证据 / Done 证据 | `docs/research/` + `data/` | 沿用（阶段二归档） |
| **Context / 会话交接** | —— 缺 | **新增** `docs/progress/LAST_SESSION.md` |
| **Done 执行报告** | —— 缺（旧靠 CHANGELOG） | **新增** `docs/progress/done/` |
| **AI 入口 / 核心记忆** | —— 缺 | **新增** 根目录 `AGENTS.md` |

方法论来源（一手，台账 §10 已载）：Documentation First DDD V2、Vibe-Coding-Sample DDD、blog.vibecoder 2026、github/spec-kit。**不引入任何 CLI / 工具链依赖**（P1）。

## 2. 单次任务闭环（按规模伸缩，P3）

**没有固定步数**。按任务大小选路径，可跳过不适用步骤但要留痕说明。

### 2.1 大任务（新体系 / 新玩法 / 架构变更）——完整链路

借鉴 spec-kit `specify→plan→tasks→implement→converge`，落到本仓：

1. **对齐**：读 `AGENTS.md` → `LAST_SESSION.md` → 台账相关裁决 → 相关 ADR / design。
2. **写规格**（小而明确，含验收标准）：写进任务临时说明或 `docs/progress/done/` 的目标段；**规格聚焦「做什么行为 + 边界 + 验收」，不堆实现细节**。
3. **决策检查**：若触及固定裁决/许可证/产品定义 → 发起 L2 询问 → 先固定入台账（L1 用 ADR，L0 直修留痕）。
4. **实现**：复用优先，先搜开源成品与官方文档。
5. **验证**：够用的最小充分证据即可（见 §4，无强制门禁）。
6. **回写**：done 报告（目标/改动/验证/遗留）+ 同步受影响的文档 + 更新 `LAST_SESSION.md`。

### 2.2 小改动（文案 / 单参数 / 明显 bug）——精简路径

**读现场 → 改 → 验（能验证就验证）→ 留痕**（在 `LAST_SESSION.md` 记一行即可，无需单独 done 报告）。比例原则优先，别为一句话改动走全套流程。

## 3. 交接与 done 报告（P2 / P4 · 轻量留痕）

落点由主管定（P4 授权），原则是「**上下文压缩后 AI 仍能记得看**」：

| 文件 | 角色 | 格式 |
|---|---|---|
| `AGENTS.md`（根） | AI 第一站 + 现场指针 | 极简项目卡，不放长文 |
| `docs/progress/LAST_SESSION.md` | 会话交接（每轮收尾更新） | 四段式：已完成 / 未完成 / 阻塞 / 下一步 |
| `docs/progress/done/<编号>-<主题>.md` | 任务执行报告（有实质任务才写） | 目标 / 改动文件 / 验证证据 / 遗留 |
| `docs/progress/README.md` | 目录说明 | 一页 |

**3S 纪律**（写面向 AI 的文档时）：**S**elected 仅必要、**S**ynthetic 精简提炼、**S**tructured 结构化。文档是给 Agent 读的，噪音即成本。

**留痕而非防护**（P2-补）：AI 可直接修订任何文档；约束是「修订可追溯、不绕过裁决」，不是「禁止修改」。done 报告与交接文件就是留痕载体。

---

## 4. 验证：无强制门禁（P5）

- **后续开发不设强制 CI 门禁**：不在每个任务收尾强制跑 golden-cases / license-scan / schema-validate。
- done 报告**如实记录**实际做了哪些验证、未做的说明原因；质量靠「数值零错红线 + 最小充分证据 + 用户随时可打断」保障。
- **历史资产保留不动**：`verify_m0_s2.py`（41 断言）、`verify_auth_s2.py`（38 断言）及其 CI 接入是阶段二已归档、已证明不确定性消解的历史证据（L0 史料），**不因 P5 删除或停用**。
  - 一句话区分：**历史门禁 = 证据（保留）；后续开发 = 无闸门（不新增）**。

## 5. 决策与变更流转（沿用 docs/12 分级）

| 级别 | 定义 | 处理 |
|---|---|---|
| **L0** | 文案纠错、过时口径更新、明显 bug、文档与实证冲突的修正 | 主管直修 + 留痕（P2-补明确鼓励） |
| **L1** | 技术选型、架构调整、非固定裁决的设计变更 | 提 ADR → 同步文档 → 登记台账 |
| **L2** | 触及 CHARTER 固定裁决、产品定义、许可证基线、里程碑验收口径 | **发起询问 → 用户裁决 → 逐批先固定入台账** |

**矛盾处置节奏**：主管发现 L2 项随时发起询问；按批（每批先固定入台账）推进，不攒到最后；不替用户裁决。

## 6. M1 起的里程碑推进（P6 薄切片）

M1「一个完整体系跑通全链路」按**薄切片**逐条推进，每条是一个 DocDD 闭环，逐个跑通再集成：

1. 骨架搭建（前后端常驻 + Docker Compose 单机自托管）
2. 内容 schema（真实反应库 + 静态参数物化层，复用 `docs/design/03`）
3. 单体系求解（phreeqpython 主引擎 + 黄金用例）
4. 物种面板（solution_speciation + 时间轴）
5. 容器内 WASM 现象表现
6. 实验报告
7. 时间轴回放与集成

切片顺序可按实测反馈调整（P3 灵活原则）；每片验收以「可跑通 + 数值零错 + 有证据」为准，不堆数量。
