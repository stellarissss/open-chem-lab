# 04 · 美术资产管线（出版级写实 2D）

> 目标：把 `tikz-chemlab`（LPPL，需转换）的编译输出物转成产品可用的**写实 2D 实验台器材**；`@itkdm/open-lab-components`（MIT）仅作 **UI 元素与缩略图**。全程不重复造轮子、不踩许可证红线。
> 依据：台账 5.3 / 6.3（C19 销项）、`research/03`、ADR-0004（LPPL 输出物）、ADR-0007（2D 写实实验台 + 分子级 3D）、**ADR-0009 / 台账 §9（D5、D8）**。
> **v2.0**：初版「双层皮肤可切换 / 程序化 3D 器材 / `assets/structure/`」已作废；主调固定为**出版级写实 2D**，3D 只做分子 / 晶体。
> **v2.1（2026-11-15，M0 实测后）**：转换链由 `DVI → dvisvgm` 改为 **`lualatex → PDF → pdftocairo -svg → svgo`**（唯一实测可行路径，D5）；`open-lab-components` 经核实为 **HTML fragment 库、非 React**，简笔示意风与写实主调冲突，用途收窄为 **UI / 缩略图**（D8），「StrictMode 重复 DOM」验收项作废。

## 二、管线 B：open-lab-components → UI / 缩略图（零转换成本）

**M0 实测形态**：`index.js` 提供 `list/get/readSync/load`，`components/**/*.html` 为 HTML 片段；**不是 React 组件库**。共 210 组件 / 化学相关 35 个，SVG + 14 个 `--cmp-*` CSS 变量、内联 `<script>`，简笔示意风（无 `linearGradient` / 无滤镜 / 无高光）。因此：

- 以 **CSS 变量注入或 Web Component 封装**接入 UI / 缩略图，不写 React 包装层、不把片段手工改成 JSX；
- 仿真状态（液位、颜色）需要映射时，直接改 `--cmp-*` CSS 变量，无需重绘；
- **不得把该库用于实验台写实主视图**——写实器材一律走管线 A 的 tikz-chemlab 输出物。

```ts
// packages/lab-components/src/mountFragment.ts（示意，约 20 行）
import * as lab from '@itkdm/open-lab-components';

export function mountFragment(id: string, host: HTMLElement, vars: Record<string, string>) {
  const html = lab.readSync(id);
  host.innerHTML = html;
  for (const [k, v] of Object.entries(vars)) host.style.setProperty(`--cmp-${k}`, v);
}
```

**注意事项**：

- ~~React 18 StrictMode 双调用 effect → 必须 `unmount` 清理干净~~：**该验收项已作废**（库非 React，D8 / M0 §4.4）。
- 固定 npm 版本（`0.1.1`），CI 跑其 `npm run validate` 的等价检查；不把 `registry/*.json` 当手写数据。
- **写实一致性**：简笔示意风与出版级写实主调冲突，故不进主视图；UI / 缩略图用途下不要求写实一致，但须在 `ASSETS.csv` 的 `used_in` 标注 `ui/thumbnail`，便于 CI 校验用途边界。

## 三、管线 A：tikz-chemlab → 分层 SVG（主资产，核心转换）

### 3.1 合规边界（ADR-0004，先于技术）

```
构建期（Docker 内）：从 CTAN 拉取 tikz-chemlab 源码（.sty/.tex/Obj.tex）
   → lualatex 编译为 PDF
   → pdftocairo -svg 转 SVG → svgo 优化
   → 只把 SVG 产物写入 assets/labware/
   → 宏包源码不进仓库、不随产品分发
仓库内：只保留「生成脚本 + 器材参数表 + SVG 产物 + 署名」
```

依据 LPPL 1.3c **Clause 1**：「the act of running the Work is not restricted and no requirements are made concerning any offers of support」→ 编译输出物不受 LPPL 分发条款约束。若将来要**修改宏包源码再分发**，则触发 Clause 6（改名 + 变更日志 + 附原始未修改副本），必须单独 `upstream/` 目录隔离并新增 ADR。

### 3.2 构建镜像与命令（M0 实测通过，D5）

**M0 实测结论**：原规划的 `DVI → dvisvgm` 与 `dvisvgm --pdf` **双路径均失败**（前者 `PostScript error: undefined in pgfwOperand`，后者因 Ghostscript 10.02.1 不被 dvisvgm 3.2.1 支持）。唯一可行路径为 `lualatex → PDF → pdftocairo -svg → svgo`，产物**优于规划预期**：纯 `<path>`、零 `<text>` / 零外部字体 / 零外部位图、21 个 `clipPath`、保留 `<g>` 分组、`liquidLevel1` 液位可控。

```dockerfile
# tools/asset-pipeline/Dockerfile（M0 实测）
FROM texlive/texlive:latest
RUN apt-get update && apt-get install -y --no-install-recommends \
      poppler-utils && rm -rf /var/lib/apt/lists/*
# npm i -g svgo 用于产物优化
```

```bash
# tools/asset-pipeline/build-tikz.sh（M0 实测，逐器材生成）
set -euo pipefail
MACROS=(TestTube HeatTube RoundFlask HeatFlask Funnel GraduatedCylinder \
        Pipette LargePipette Titration Distillation SeparatoryFunnel Stand Column)
for m in "${MACROS[@]}"; do
  cat > "build/\\tkz${m}.tex" <<TEX
\\documentclass[tikz,border=2pt]{standalone}
\\usepackage{tikz-chemlab}
\\begin{document}
\\begin{tikzpicture}[scale=1.2]
  \\tkz${m}
\\end{tikzpicture}
\\end{document}
TEX
  # 唯一实测可行路径：lualatex → PDF → pdftocairo -svg → svgo
  lualatex --output-directory=build "build/\\tkz${m}.tex"
  pdftocairo -svg "build/\\tkz${m}.pdf" "assets/labware/\\tkz${m}.svg"
  svgo --multipass "assets/labware/\\tkz${m}.svg"
done
```

> **已废弃**：`lualatex --output-format=dvi`、`dvisvgm --pdf --font-format=woff`、`pdf2svg` 路线。禁止在双平台脚本中回退到这些命令。

**参数化批量生成**：利用宏包选项一次生成变体（液位 `liquidLevel1=0/25/50/75/100`、液体颜色 `liquidStyle`、倾斜 `tiltAngle`、塞子 `stopper`、滴定管 `buretteLevel`、`TapOpen`），产出 SVG 序列，支撑液位动画与不同试剂外观。M0 已核实 `liquidLevel1=85` 与默认 50 的 SVG `clipPath` 路径确实不同（Y 从 367.84 → 338.15）。

### 3.3 转换后的技术处理（预料中的问题与预案）

| 问题 | 预案 / M0 结论 |
|---|---|
| TikZ 输出把「玻璃」与「液体」画在同一路径，无法单独改液位 | ① 用 `standalone` + 分层 `scope` 生成两个 SVG 再合成；② 用 `liquidLevel=0` 与 `=100` 两张 SVG 做差集，程序化提取液体层；③ **推荐**：把液位做成 `clipPath` 遮罩，只用一张玻璃 SVG（M0 实测产物已自带 21 个 `clipPath`） |
| 字体被转成 `<text>` 依赖本机字体 | **M0 实测已消解**：`pdftocairo -svg` 产物为纯 `<path>`、零 `<text>` / 零外部字体。原 `dvisvgm --font-format=woff` / Inkscape 转曲预案作废 |
| 渐变 / 图案（`shadings`/`patterns`）在 SVG 中丢失 | 后处理用 CSS 渐变替换；或在产品侧用材质层覆盖 |
| SVG 体积大、含编辑器元数据 | `svgo --multipass`；移除 `sodipodi` / `inkscape` 命名空间 |
| `scale` 与坐标系不一致 | 统一 `viewBox`，在器材参数表里记录 `baselineY` 与 `mouthY`（液面 / 瓶口的 y 坐标），供实验台定位 |
| 颜色是硬编码 TikZ 色 | 生成后把关键 `fill` / `stroke` 替换为 CSS 变量 `var(--glass)` / `var(--liquid)` |

### 3.4 动态化：一张 SVG + 三个变量

```tsx
// 液位用 clipPath，颜色用 CSS 变量，倾斜用 transform —— 不为每个状态生成一张图
<BeakerSvg
  style={{
    '--liquid': material.color,
    '--liquid-level': `${(volume / capacity) * 100}%`,
    transform: `rotate(${tilt}deg)`
  } as React.CSSProperties}
/>
```

> 此处 `BeakerSvg` 是**产品自有的 React 组件**，用于渲染管线 A 的写实 SVG；与「open-lab-components 非 React、不写 React 包装」不冲突。tikz-chemlab 的「参数化」优势保留在**构建期**（生成不同器材 / 装置），运行期动态性由 CSS / clipPath 承担，避免资产数量爆炸。

## 四、管线 F：分子级 3D 视图（唯一 3D 用途）

| 需求 | 组件 | 输出 |
|---|---|---|
| 分子 / 晶体 / 球棍模型 | **3Dmol.js**（BSD-3-Clause，M0 已销项 F2） | WebGL 可缩放旋转的 3D 结构；支持 pdb / sdf / mol2 / xyz / cif / mcif / pqr |
| 结构式 2D | SmilesDrawer / Kekule.js / RDKit.js | 运行时生成 SVG |
| 微观视图 | 由 `solution_speciation` 驱动 | 分子 / 离子运动、键断裂与形成示意 |

- **3Dmol.js 论文引用**：DOI `10.1093/bioinformatics/btu829`（Rego & Koes, *Bioinformatics* 31(8):1322-1324），M0 经 Crossref 核实，已补齐并写入 `ASSETS.csv` 与 About 页。
- 备选：Mol* (MIT) / NGL Viewer (MIT)。
- **不做**：程序化 3D 器材、批量器材 GLB、轮廓点集提取、玻璃 `MeshPhysicalMaterial` 调优（长线，需单独 ADR）。
- 3D 场景只放分子 / 晶体，**不与容器内现象渲染抢 60fps 帧预算**（SP-1）。
- **阶段二收尾已补验**：纯 `--headless` 无 X display 时 SwiftShader `clearDepth` 为 null 的根因已定位（`xcb_connect() failed`）；用 Xvfb + SwiftShader 拿到 WebGL 2.0，乙醇 9 原子球棍渲染 `hasGeometry=true`。见 `04-M0验证报告` §5.5。M1 在真实 GPU 浏览器复核即可。
