#### 【补正 A】4.1 的事实层更正（主管补正，**不推翻裁决**）

- ✅ **成立的部分**：Apache-2.0 主产品与 LGPL-2.1 库**可以合法共存**，且**不会传染**主产品许可证 —— LGPL 的设计目的本就是「permit linking those libraries into non-free programs」。所以「Reaktoro 进主链」在法律上完全可行，**裁决保留**。
- ⚠️ **需修正的部分**：「开源产品 ⇒ 许可证自动合适」不成立。依据本轮读取的 **LGPL-2.1 许可证原文**：
  - §5：「a 'work that uses the Library' … in isolation, is not a derivative work … linking … creates an executable that is a derivative of the Library … covered by this License」；
  - §6：允许按自定义条款分发，但必须 ① 显著声明使用了该库并附 LGPL 全文；② 允许客户为自用修改、并**为调试此类修改做逆向工程**；③ 满足 a~e 之一 —— **若把库源码静态并入主二进制，须随附完整可重链接的目标文件/源码**；采用**动态链接 + 库可替换**则落在最宽松路径。
- **落地（保持「进主链」不变）**：Reaktoro 作为主链的**动态链接、运行时可替换组件**接入（不把 C++ 源码静态编进主二进制），同时配齐 §6 义务清单：显著声明、`NOTICE`/`CREDITS.md` 署名与 LGPL-2.1 全文链接、保证可替换、允许逆向调试、修改版源码可得。这样既是主链组件、零合规风险，用户还能自行换库版本。
- **必须同步**：撤销 `ADR-0005` 中「LGPL 列灰名单 / 不链接」条款，改写为「LGPL-2.1 动态链接准入 + §6 义务清单」；CI 增加「动态链接 / 可替换性」检查。

### 2.5 SP-1 · 自适应定量调度全局最优方案（主管依 4.3 授权产出）

> 目标：兑现「不自适应硬编码阈值 / 把算力给到正在观察的过程 / 60fps 与定量求解协同 / 追求全局最优 / 不拖累进程」，且**全部复用现成范式，不造轮子**。

**现成基石（本轮 GitHub 实测核实）**：

| 组件 | ★ | 许可 | 用途 |
|---|---|---|---|
| **SUNDIALS CVODE/CVODES**（`LLNL/sundials`） | 707 | BSD-3 | 自适应步长 BDF/Adams 刚性 ODE 积分，误差容差驱动；Cantera/ChemPy 底层即它 |
| SciPy `solve_ivp`（`scipy/scipy`） | 15217 | BSD-3 | 自适应 RK45/BDF 参考实现 |
| Cantera | 885 | BSD（API 显示 NOASSERTION，M0 复核） | 动力学 / 热力学 |
| ChemPy | 660 | BSD-2 | 电解质平衡 + 动力学 |
| pyequion2 | 35 | BSD-3 | 物种分布 / 活度 / pH |
| **Significance Manager / simulation LOD** | — | **借鉴的调度范式（概念，非实测仓库）** | 按「观察者关注度」分配更新预算；见 §7.4 F4，与上方「已核实库」区分 |

**四层解耦架构**：

1. **数值自适应层（消灭硬编码阈值）**：求解步长由 CVODES 的**局部误差估计 + `rtol`/`atol` 容差**自动决定，刚性检测自动在 BDF ↔ Adams 间切换。快反应（电离/水解/酸碱，τ→0）走代数平衡直接求解、慢反应走 ODE 积分 —— **分类由数值刚性自动判定，不是人为拍 τ 阈值**。直接兑现「不人为硬编码阈值、实时间隔长短自适应」。
2. **算力调度层（把算力给到正在观察的过程）**：引入游戏引擎成熟的 **Significance Manager** 范式，为每个容器/反应计算「关注度分数」= 视野内 + 刚被操作 + 有可见现象 + 时间轴聚焦。高分 → 高频高精度实时求解；低分 → 降频 / 粗粒度 / 冻结并复用缓存。总算力按**帧预算（16.7ms）动态配额**，而非固定分层。兑现「把算力给到正在观察的反应/过程，体验优先」。
3. **表现解耦层（60fps 不被求解拖累）**：WASM 粒子/物理表现按固定 60fps 独立渲染；求解结果以「物种分布快照 + 时间戳」异步喂入，中间用插值/外推平滑。**求解耗时与帧率彻底解耦**，重体系不掉帧。兑现「确保 60fps 与定量求解协同」。
4. **事件唤醒 + 缓存层**：加料 / 加热 / 改参数 / pH 突变等事件立即唤醒相关体系重算；稳态冻结不重复求解，平衡态结果缓存复用（呼应既有「热/温/冷路径」设计）。

**验收口径**：注意力焦点内反应数值零错（红线 3.3）；帧率恒 ≥ 60fps；焦点外体系算力占用随关注度单调下降；新增体系**无需改调度代码**（数据驱动，呼应 ADR-0006 重写）。

**落地位置**：`design/02` 新增「调度层」章节、新增 `ADR-0008 自适应定量调度`、`design/07` 性能预算按帧预算重写、规则 schema 增 `rtol/atol/stiffness/significance` 字段。

**合规**：SP-1 全链 BSD-2 / BSD-3 / Apache-2.0，**不引入任何 GPL 组件**；Reaktoro 按【补正 A】动态链接接入。

**核实结论（逐条，均为官方原文要点）**：

| # | 事实 | 官方依据 |
|---|---|---|
| B1 | **LGPL-3.0 不是独立许可证**：其正文开篇为「incorporates the terms and conditions of version 3 of the GNU General Public License, supplemented by the additional permissions listed below」——即 **GPLv3 全文 + 附加权限**。 | LGPL-3.0 正文引言 |
| B2 | 因此采用 LGPL-3.0 的产品，**必须随附 GPLv3 全文 + LGPL-3.0 全文两份文本**；Combined Works 第 4 节要求「prominent notice that the Library is used」「accompany with a copy of the GNU GPL and this license document」。 | LGPL-3.0 §4(a)(b) |
| B3 | **Apache 的 `NOTICE` 机制不再适配**：换证后合规义务从「Apache NOTICE 归因」变为「LGPL 显著声明 + 双许可证全文 + 允许逆向调试 + 库可替换（§4(d) 动态链接或提供可重链接材料）」。 | LGPL-3.0 §4 |
| B4 | **LGPLv3 与 GPLv3 兼容**（FSF：「It is compatible with GPLv3」）；**LGPLv2.1 与 GPLv2、GPLv3 均兼容**（FSF 明确）。 | FSF license-list #LGPLv3 / #LGPLv2.1 |
| B5 | **Apache-2.0 与 GPLv3 兼容**、与 GPLv2 不兼容；MIT/BSD-3/ISC 均为 GPL 兼容的宽松许可。 | FSF license-list #apache2 / #ModifiedBSD |
| B6 | **AGPLv3 与 GPLv3「technically not compatible in a strict sense」**，仅允许在同一项目中合并「独立模块/源文件」，且各自 §13 生效。 | FSF license-list #AGPLv3.0 |

**因此裁决 A1 的三项真实影响（主管须让用户知情）**：

1. **裁决成立、可执行**：改 LGPL-3.0 后，Reaktoro(LGPL-2.1)、全部 MIT/BSD/ISC/Apache 依赖仍可并入（B4/B5），§6/§4 义务由「跨许可证链接」变成「同为 LGPL 家族」，心理与文书上都更顺。✅ 采纳。
2. **反而解锁了原先被 ADR-0005 隔离的 GPL-3.0 组件**：The Powder Toy、PhET、H5P core 均为 GPL(-3.0)，因 LGPLv3↔GPLv3 兼容（B4），**理论上可以链接进 LGPL-3.0 主产品**。这派生出一个必须由用户裁决的新问题：**是否重做「不重复造轮子」选型、把这些原本「仅参考」的 GPL 组件纳入主链**（登记为 C14，见 §4）。
3. **换证不是「解决合规风险的必需手段」**：补充 A 已证明 Apache-2.0 + LGPL-2.1 动态链接本就零风险；A1 的真实价值是「主动选择弱 copyleft + 解锁 GPL-3.0 生态 + 要求衍生回馈」，而非补合规窟窿。**AGPL（tptmp）仍严格不兼容，必须继续隔离**（B6）——换证不能解决它。
