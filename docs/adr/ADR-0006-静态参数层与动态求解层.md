- **依据**：台账 2.3、3.3、3.4、4.4、10.3、§7.4 F1；ADR-0002、ADR-0008
- **关联**：`design/02`、`design/03`、`design/05`、`design/07`、`research/02`

## 变更史

| 版本 | 决策 | v2.0 调整原因 |
|---|---|---|
| v1.0 | fork Sandspiel，把 `Species` 枚举与 `match` 反应改成**数据驱动材质表 + 本地二进制规则包**，断网可玩 | 台账 2.3 把 L2 从「冷路径补充」升为**实时主计算层**；3.4 要求「一切分析必须定量、动态实时求解、动态+静态」；4.2 废弃断网；6.1 废弃落沙基座。**内核从「静态规则表」升级为「静态参数层 + 动态求解层」** |

## 背景（保留初版源码实读结论，作为「数据驱动」依据）

2026-11-14 实读 `MaxBittker/sandspiel` 的 `crate/src/species.rs`：

```rust
#[repr(u8)]
pub enum Species { Empty=0, Wall=1, Sand=2, Water=3, /* …约 20 种，u8 硬编码… */ }

impl Species {
    pub fn update(&self, cell: Cell, api: SandApi) {
        match self {
            Species::Sand  => update_sand(cell, api),
            Species::Water => update_water(cell, api),
            /* 每种物质一个硬编码分支 */
        }
    }
}
// 反应 = 邻域采样 + 硬编码 if/else
```

**结论（仍然成立）**：反应逻辑与物质种类**编译期固定**，每加一个物质 / 反应都要改 Rust 并重编译 WASM —— 与「1000 个反应下限、长期可维护」根本冲突。因此**物质定义与反应逻辑必须数据驱动**。

但 v2.0 中该结论的落点变了：Sandspiel 落沙基座已随实验台范式**整体退场**（台账 6.1），数据驱动不再体现为「改造本地 WASM 网格」，而体现为**服务端「静态参数层 + 动态求解层」**。

## 决策

### 1. 静态参数层（事实层，可审计、可回滚）

`content/rules/*.yaml` 是**唯一事实源**，每条参数必须包含：

| 字段 | 说明 |
|---|---|
| `source` | **权威源**：NIST / CRC / IUPAC / 课标附录 / 开放教材（台账 10.3） |
| `confidence` | `verified`（进沙盒）/ `extracted`（ORD 抽取，需复核）；**禁止 ML 猜测** |
| `applicability` | **适用条件**：温度、浓度、溶剂、离子强度、pH 范围、压强、相态、催化剂 |
| `equilibrium` | Ka / Kb / Ksp / E° / ΔG —— **定量，非近似** |
| `kinetics` | 速率模型、活化能（如适用） |
| `stoichiometry` | 计量系数（守恒校验） |
| `numerics` | `rtol` / `atol` / `stiffness: auto` / `significance: auto`（呼应 ADR-0008） |
| `effects` | 现象指令（不是渲染代码） |
| `i18n` | 物质名 / 术语 / 方程式中英双语 |

- **验算流程（台账 4.4 / 10.3）**：权威源 → **AI 用 ChemPy / Cantera 独立对拍** → **用户人工签核** → **黄金用例进 CI**；错了不许进沙盒。第二复核人 = AI 独立对拍 + 用户签核（C4 销项）。
- `rule_revision` 记录变更历史，禁止原地覆盖；`ruleset-core-YYYY.MM.DD` 版本化。
- 严格真实库：虚构物质、用户规则、MOD、规则包工坊一律不进（台账 5.4 / 6.4）。

### 2. 动态求解层（服务端实时主计算层）

- 服务端常驻，按容器实时求解：**物种分布、化学平衡、反应动力学、pH / 浓度 / 活度、电离度、沉淀与络合、热效应**。
- 全部复用现成求解器（**不造轮子**）：SUNDIALS CVODE/CVODES（自适应步长与刚性检测）、SciPy `solve_ivp`、Cantera、ChemPy、pyequion2、Reaktoro（动态链接）。
- **快 / 慢反应分类由数值刚性自动判定**，不人为拍 τ 阈值（C3 销项）；代数平衡直接求解 + ODE 积分。
- 结果与时间轴以「物种分布快照 + 时间戳」形式输出，见 `design/03` 的 `solution_speciation` / `speciation_timeline`。

### 3. 现象指令协议（事实层 ↔ 表现层唯一契约）

```json
{
  "protocol": "st.phenomenon.v1",
  "container_id": "vessel_3",
  "timestamp_ms": 4200,
  "speciation": { "H+": 1.0e-7, "Na+": 0.1, "Cl-": 0.1, "...": "..." },
  "effects": [
    {"type": "color_lerp", "from": "#ffd0d0", "to": "#e8f4ff", "duration_ms": 800},
    {"type": "temperature", "curve": [[0,25],[2,41],[10,25]]},
    {"type": "ph", "curve": [[0,1.0],[4,7.0],[8,13.0]]},
    {"type": "sound", "id": "fizz_soft"}
  ],
  "fallback": null
}
```

- 服务端只返回「发生了什么」，不关心画面；**求解层只认识物种与数值，不认识渲染**；WASM 表现层只认识现象 ID，不认识化学分子。
- 渲染器可替换；求解结果异步喂入、插值平滑（ADR-0008 第 3 层）。
- 未命中明确返回 `{"fallback":"no_visible_change","hint":"…"}` 并记入补体系日志；**绝不用近似或 ML 猜测填补**。

### 4. 数值零错红线（CI 强制执行）

| 检查 | 说明 |
|---|---|
| 计量守恒 | 反应前后元素守恒（RDKit 校验） |
| 条件互斥 | 同一 `(反应物集合, 适用条件桶)` 不得存在两条 `verified` 参数 |
| 置信度闸门 | 非 `verified` 不得进沙盒 |
| 来源完整性 | `source` 必填；`extracted` 必须带 ORD dataset_id / reaction_id |
| **黄金用例集** | 中和、制氧、置换、沉淀、电解、弱酸碱电离、水解、络合… 逐条断言**产物、方向、计量、平衡趋势、pH / 浓度数值** |
| 许可证标记 | ORD 衍生规则带 `CC-BY-SA-4.0` 溯源字段 |
| AI 对拍记录 | 每条参数附独立复算结果与签核人 |

## 理由

1. **零科学性错误可执行**：把「正确」拆成「静态已验算参数 + 动态实时求解 + CI 黄金用例」三道闸门。
2. **不重复造轮子**：求解器全部复用成熟 BSD / LGPL 项目；自研只在参数编排、现象映射、内容精校。
3. **可演进 / 可替换**：参数与求解器、求解器与表现层解耦，换求解库、加体系都不重写引擎；新增体系**无需改调度代码**（数据驱动，呼应 ADR-0008）。
4. **可审计 / 可回滚**：参数是带来源与置信度的文本，支持 diff、review、`rule_revision` 回滚。

## 影响

- `design/02` 定义静态参数层 + 动态求解层 + SP-1 调度；`design/03` 给完整 schema 与 `solution_speciation` / `speciation_timeline`；`design/05` 把 `content/` / `schemas/` / `chem-worker` 列为独立目录与包。
- `design/07` CI 门禁增「AI 对拍记录 + 黄金用例数值断言」。
- 早期「本地二进制规则包 Top-N」「IndexedDB 缓存」「夜间重编译下发」「表现型材质 ≤512」「Cell 8 字节」等设计全部作废（C8 / C29）。

## 反面约束

- 禁止把反应重新硬编码回 `match` 分支或任何编译期常量表。
- 禁止在化学事实层引入近似规则、ML 猜测产物或未签核参数。
- 禁止以「自由度」为名引入虚构物质、用户自制规则或规则包工坊。
- 禁止把求解结果直接写成脚本动画而绕过动态求解层（隐藏反应必须真实发生）。
