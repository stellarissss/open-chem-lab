# ADR-0002 · 混合分层仿真，不做「万能反应预测」

- **状态**：已接受（需求方 2026-11-13 四项决策之一，写入 `CHARTER` D1）
- **关联**：`CHARTER` D4、`design/01`、`design/02`、`design/03`、`research/01`

## 背景

需求方提出「NB实验室的核心功能是仿真模拟几乎所有常规的几万种物质、反应、器材」，并选定「全量上万物质/反应」。但两轮调研确认：

1. NB 官方口径是化学单科近 200 个经典实验、1000+ DIY 器材；它是**预置模板 + 引擎驱动现象**，不是通用反应预测器。
2. 化学上，「任意两种物质混合会生成什么」**不可判定** —— 取决于温度、浓度、溶剂、pH、压强、相态、催化剂、光照、时间、容器材质。
3. 客户端 60fps 网格只能承载几百种表现材质，物理上无法把上万化合物塞进粒子引擎。

## 备选

| 方案 | 判断 |
|---|---|
| 纯现象级规则引擎 | 最贴近 NB 真实玩法、最快可玩，但规模止于几百到几千物质，无法兑现「上万」 |
| 纯数据/计算驱动（PubChem + ORD + RDKit 反应预测） | 科学性强、规模大，但实时性差、正确性无法全覆盖、很难做成好玩的沙盒 |
| **混合分层** | 规则引擎保实时好玩，数据库保规模，服务端计算保科学扩展 |

## 决策

**四层混合架构**（L0 表现 / L1 规则 / L2 计算 / L3 数据），并把「上万」拆成三个互不混同的概念：

| 概念 | 量级 | 获取方式 |
|---|---|---|
| 可查询化合物 | 10k–100k | PubChem / Wikidata 批量导入「资料卡」 |
| 可反应物质 | 数百–数千 | ORD + SMARTS 模板抽取 + **人工精校** |
| 表现型粒子 | ≤ 512 | 规则引擎的表现材质，与化合物库多对一映射 |

**明确不做**「输入任意两种物质自动算产物」的承诺。规则带 `conditions / confidence / source / effects`；未命中返回 `{"fallback":"no_visible_change","hint":…}` 并写入未覆盖日志，形成补规则的数据飞轮。

## 理由

1. **好玩与规模解耦**：L0 只依赖本地规则包，断网可玩，与数据库规模无关。
2. **正确性优先**：`verified` 规则才进实时沙盒；低置信规则只作图鉴，避免「错误的反应比没有反应更糟」。
3. **诚实**：承认化学不可判定性，避免做出既不好玩也不科学的四不像，也避免产品虚假宣传。
4. **可演进**：L2 服务端计算与 L3 数据库可在不改动 L0 的前提下持续扩展。

## 影响

- `design/03` 定义 `compound / substance / material` 三层表与映射。
- `design/01` 定义热/温/冷三级路径与预计算飞轮。
- 产品文案统一「教学近似，非实验级数据」；不做万能预测宣传。
- 目标实际**高于 NB**（NB 近 200 实验 vs 我们上万资料卡 + 数千规则），但靠分层兑现，不靠硬堆。

## 反面约束（不可绕过）

任何把「未命中组合」悄悄用 ML 猜一个产物塞进沙盒的实现，都违反本 ADR 与 `CHARTER` 第 0 条（正确性优先），必须先修订本 ADR。
