## 一、背景：M0 把纸面选型放进真实环境后暴露的偏差

| # | 阶段一规划 | M0 实测 | 影响 |
|---|---|---|---|
| 1 | `chempy` 作水溶液平衡主链 | 直接依赖 **46** 个、经 `pyodesys` 拖入 Jupyter 整栈；`python:3.11-slim` 内 `pip install chempy` **>34 分钟未完成**；稳态求解约 11.5ms | 与「单机自托管、全局总成本最低」（CHARTER 第 2 条）冲突 |
| 2 | `phreeqpython / PHREEQC` 标「许可证未定、暂不纳入」 | 实为 **Apache-2.0**；直接依赖 **3** 个；单次 **<1ms**；官方用例 **9/9 PASS**；`species`/`si`/`desaturate`/`add()`/溶液混合运算逐条对口核心需求 | 阶段一事实判断需更正 |
| 3 | `Reaktoro` 主链动态链接 + 预设 pip/Docker | **PyPI 404**，仅 conda-forge 2.13.0；验证项 9「运行时替换版本」无法按原设计执行 | 渠道与部署链不一致 |
| 4 | 资产转换 `DVI → dvisvgm --pdf` | 两条路径均失败（PGF PostScript specials / Ghostscript 10.02.1 不被 dvisvgm 3.2.1 支持）；`lualatex → PDF → pdftocairo -svg` 通过且产物质量优于预期 | 命令错误，阻塞资产管线 |
| 5 | `open-lab-components` 为 React 组件、可作辅资产 | 实为 **HTML fragment 库**（210 组件 / 化学 35），零依赖、SVG + CSS 变量、简笔示意风无渐变高光 | 形态描述错误 + 与写实主调冲突 |
| 6 | 刚性积分以 CVODES 为主链 | SciPy **LSODA 内置 Adams/BDF 自动刚性切换**：262 次 / 1.48ms vs RK45 42500 次 / 259ms（约 **175 倍**），比 BDF 快约 14 倍，且免编译 | 可免编译兑现台账 4.3 |
| 7 | 网关 Fastify / axum「M0 二选一」 | axum 16806 rps vs Fastify 4542 rps，但求解本身约 11.5ms 量级，网络层非瓶颈；axum 首次编译约 5 分钟且依赖多次超时 | 维护成本应优先于吞吐 |

## 三、求解器链分层设计（依 D2-补「由你设计」授权）

### 3.1 分层与数据流

```
[浏览器] 实验台交互 / 写实 2D / 物种面板 / 时间轴 / 分子 3D / 容器内 WASM 现象
    │ REST + WS
[gateway] Fastify (Node/TS) —— 鉴权 · 会话 · 限流（D4）
    │
[solver-worker] Python 3.11 —— 唯一事实源入口（主链）
    ├─ phreeqpython / PHREEQC（Apache-2.0）  常规水溶液 · 电解质体系（绝大多数反应）  [D1]
    ├─ SciPy LSODA / BDF                     动力学 ODE · 内置自动刚性切换           [D3]
    ├─ Cantera（BSD-3）                      燃烧 / 爆炸瞬态动力学 · 热力学
    ├─ chempy（BSD-2）                       AI 独立对拍（不参与主求解）            [D1]
    ├─ pyequion2（BSD-3）                    活度 / 离子强度辅助
    └─ 按需路由 ──UDS/protobuf──▶ [reaktoro-service] 独立微服务（conda 镜像）       [D2 / D2-补]
                                    多相 · 固相 · 气相 · 高温高压 · 燃烧爆炸平衡终态 · 复杂体系
    │
[solution_speciation / st.phenomenon.v1] → 快照异步喂入 WASM 表现层（60fps 解耦，SP-1）
```

### 3.2 事实源唯一性（防止双事实源分裂）

- **主链是唯一事实源入口**：所有求解请求先到 `solver-worker`；`reaktoro-service` 由服务端按「体系特征」**按需路由**，两服务**不并行重复求解同一体系**。
- 路由判定维度：相态数、温压条件、是否涉及燃烧 / 爆炸动力学、体系复杂度。判定表随内容管线**逐体系固化并进 CI**，不允许前端自行选择引擎。
- 两服务返回同一 `solution_speciation` 与 `st.phenomenon.v1` 结构（见 `design/03`），避免数据模型分裂。
- 事件唤醒 / 稳态冻结 / 快照缓存仍按 SP-1（`ADR-0008`）执行，跨服务请求须带超时、重试与缓存键，避免 UDS 抖动拖累 16.7ms 帧预算。

### 3.3 「剧烈燃烧 / 爆炸」的技术边界（事实零错红线）

用户 D2-补 把剧烈燃烧、爆炸归入 Reaktoro。主管依「由你设计」在**实现层**拆为三层，**不改变裁决方向**：

| 层 | 承担者 | 理由 |
|---|---|---|
| 平衡终态 / 产物组成 / 多相平衡 | `reaktoro-service`（Reaktoro） | Reaktoro 是热力学 / 多相平衡求解器 |
| 瞬态动力学 / 点火 / 火焰传播 | **Cantera**（已在链内） | 需燃烧机理；M0 实测 GRI30 绝热火焰温度 2225.5K |
| 火焰、冲击波、慢放、音效 | **容器内 WASM 表现层** | 「数值零错 / 视觉可夸张」红线：现象可夸张，数值不得近似 |

> 若把「Reaktoro 计算爆炸动力学」写成事实，会构成科学性错误；分层是为守住 CHARTER 第 0 条「事实零错」，不是替换用户裁决。

### 3.4 通讯与镜像（L1 实现细节，主管定）

- **单机自托管（D6）下优先 UDS + protobuf**：无 HTTP/2 栈、无 TCP 握手，单机最低延迟；用户裁决中的 **gRPC 选项保留**，若未来放开多机再启用（不重复造轮子，复用现成 `prost`/`tonic` 生态）。
- `reaktoro-service` 使用**独立 conda-forge 基础镜像**，把「不在 PyPI」的渠道差异隔离在单个服务内；主链保持 pip/Docker + lockfile（D7），两者互不污染。
- 进程间通讯的鉴权、资源隔离、超时 / 重试、conda 供应链审计写入 `SECURITY.md` 与 `design/07`。

### 3.5 其他选型落地

- **D5**：`design/04`、`tools/asset-pipeline`、`ADR-0004` 统一为 `lualatex → PDF → pdftocairo -svg → svgo`；旧 `DVI → dvisvgm` 命令**禁止回退**。
- **D8**：`open-lab-components` 以 CSS 变量注入 / Web Component 封装接入 UI / 缩略图；`ASSETS.csv` 的 `used_in` 必须为 `ui/thumbnail`，出现 `apparatus/*` 即违规；「StrictMode 重复 DOM」验收项作废。
- **D7**：Python 锁 3.11 + lockfile；PyPI 最新 numpy/scipy 要求 ≥3.12 的张力在 M1 前再评估，届时须重跑 M0 全部最小测试。

## 四、合规边界（LGPL-2.1 §6，D2 不改变义务）

- **独立微服务不免除 §6 义务**：动态链接、库可运行时替换、显著声明、随附 LGPL 全文、允许为调试做逆向工程、提供修改版源码可得信息，逐项仍须落地（`ADR-0005` / `NOTICE` 第 2 节）。
- 进程隔离使「可替换」更直观：替换 `reaktoro-service` 镜像内动态链接的 `libReaktoro` 即可，**主链无需重新编译**；部署说明须给出该替换入口。
- CI `lgpl-link-check` 的校验对象由「主二进制」改为「**服务镜像内的动态链接与可替换性**」；`license-scan` 白名单保持 AGPL / GPLv2-only 禁止，GPL-3.0 组件仍需 ADR。
- phreeqpython 为 Apache-2.0、Cantera 为 BSD-3-Clause、chempy 为 BSD-2-Clause、pyequion2 为 BSD-3-Clause，均与 LGPL-3.0 主项目兼容；阶段一「PHREEQC 许可证未定」的判断已作废。

## 六、后果与风险

**正面**

- 依赖量与镜像体积大幅下降（46→3 直接依赖），去除 Jupyter 整栈；求解耗时从约 11.5ms 降到 <1ms，且能力更对口「任意组合 / 隐藏化学态 / 沉淀溶解 / 事件唤醒重算」。
- conda 渠道差异被隔离在单个服务，主链 pip/Docker + lockfile 保持简洁；UDS 通讯在单机内低延迟且无额外协议栈。
- 资产管线有了唯一实测可行命令，产物零字体依赖、液位可控；写实主调与简笔 UI 资产的边界清晰。

**负面 / 缓解**

| 风险 | 缓解 |
|---|---|
| 新增 `reaktoro-service` 提高部署与运维复杂度 | 只在需要高级体系时按需启用；单机 Compose 内统一管理；`design/07` 给出服务清单与替换入口 |
| 跨进程通讯带来延迟与失败模式 | UDS + protobuf、超时 / 重试 / 缓存键；求解快照异步喂入 WASM，不占 16.7ms 帧预算；`SECURITY.md` 覆盖攻击面 |
| conda 镜像供应链与体积 | 固定版本 + 校验和；镜像内只装必要运行库；CI 增加供应链检查 |
| 两引擎职责边界若漂移会形成双事实源 | 主链唯一入口 + 逐体系固化路由判定表 + CI 校验；`design/02` 明确分工 |
| phreeqpython star 较小（★94）、活跃度需跟踪 | 固定版本 + 回归测试（沿用台账对早期项目的质量门槛）；保留 chempy 作独立对拍，避免单点 |
| D7 锁 3.11 与最新 numpy/scipy 的张力 | lockfile 固定；M1 前评估升 3.12，届时重跑全部 M0 最小测试 |
