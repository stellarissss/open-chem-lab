## 背景

主项目现为 **LGPL-3.0**（见 ADR-0001）。需要重新界定三类边界：

1. **强 copyleft / 不兼容组件**：tptmp（AGPL-3.0）、GPLv2-only。
2. **许可证层面已兼容、但依选型决策不纳入的组件**：The Powder Toy（GPL-3.0）、PhET sims（GPL）、H5P core（GPL-3.0）。
3. **带 SA 义务的数据**：`open-reaction-database/ord-data`（数据 CC-BY-SA-4.0 / 脚本 Apache-2.0）。

官方事实（2026-11-14 联网读 FSF/GNU 原文，见台账【补正 B】）：LGPLv3 ↔ GPLv3 兼容；LGPLv2.1 ↔ GPLv2/v3 兼容；Apache-2.0 ↔ GPLv3 兼容；**AGPLv3 与 GPLv3 严格意义不兼容，仅可合并独立模块**。

## 决策

### 1. AGPL 与 GPLv2-only：严格隔离（不变）

- **不 import、不链接、不合并构建产物、不移植源码进主仓、不提供任何网络服务合并**。
- tptmp（AGPL-3.0）完全不碰：FSF 明确 AGPLv3 与 GPLv3「technically not compatible in a strict sense」，换证**不能**解决它（台账【补正 B】第 3 点）。
- 允许的唯一形态：只读源码 / 文档获取设计思路。

### 2. GPL-3.0 组件：许可证可行，但**依选型决策不纳入**（台账 6.2）

| 项目 | 许可 | 状态 |
|---|---|---|
| The Powder Toy | GPL-3.0 | 只读参考。台账 6.1 已废弃无限画布落沙基座与 Sandspiel，落沙引擎失去立足点，**不重评选型** |
| PhET sims | GPL | 只读参考 / 独立页面原样自托管；官方明确「定制现有 sim 须遵守 GPL」 |
| H5P core | GPL-3.0 | 只读参考；教学层已后置长线（10.1） |
| cdk / Jmol-SwingJS | LGPL-2.1 | 仅作参考，未纳入选型 |

> **必须在 ADR-0001 与本 ADR 同时写清**：「换证解锁 GPL 生态」是**许可证立场**，「不纳入」是**选型决策**，两者不矛盾；否则日后会被质疑多此一举。若将来确需引入，必须先提 ADR 重做选型，不得静默纳入。

### 3. LGPL 库：动态链接准入 + §6 义务清单（台账【补正 A】）

**Reaktoro（LGPL-2.1）进主链**，裁决保留，但「开源产品 ⇒ 许可证自动合适」不成立。依据 LGPL-2.1 原文：

- §5：「a 'work that uses the Library' … in isolation, is not a derivative work … linking … creates an executable that is a derivative of the Library」；
- §6：分发链接作品必须 ① 显著声明使用该库并附 LGPL 全文；② 允许客户为自用修改、并**为调试此类修改做逆向工程**；③ 满足 a~e 之一 —— **若把库源码静态并入主二进制，须随附完整可重链接的目标文件 / 源码**；采用**动态链接 + 库可替换**落在最宽松路径。

**落地（保持「进主链」不变）**：

| 义务 | 落地 |
|---|---|
| 显著声明使用 LGPL 库 | `NOTICE` 第 1、2 节 + `CREDITS.md` |
| 随附 LGPL / GPL 全文 | `LICENSE.LGPL-3` + `LICENSE.GPL-3`（主项目 LGPL-3.0 已要求双文本）+ 上游 LGPL-2.1 全文链接 |
| 允许逆向调试与自用修改 | `NOTICE` 第 2 节明示 |
| **库可替换** | **动态链接 + 运行时可替换**，不把 C++ 源码静态编入主二进制；部署说明给出替换入口 |
| 修改版源码可得 | `CREDITS.md` 列上游地址与获取方式 |
| CI 校验 | 新增 `lgpl-link-check`：动态链接 / 可替换性 / 声明齐全 |

> LGPL-2.1 与 GPLv3 兼容（B4），故与主项目 LGPL-3.0 共存无法律障碍。

### 4. CC-BY-SA 数据：独立仓物理分离（台账 10.4 / M4 销项）

- `data-ord/` 为**独立公开 Git 仓库**，主仓**仅以 submodule 引用**；monorepo 目录树内**不再画 `data-ord/`**（消除初版 ADR 与 design/05 的 M4 矛盾）。
- 保留 CC-BY-SA-4.0 声明与署名；由 ORD 抽取生成的规则表单独标注溯源，与自有 `content/rules/`（LGPL-3.0）分目录。
- **只抽取事实性反应式与条件**（反应物、产物、条件、计量），不整段复制描述文本、产率叙述或数据集表述。
- 抽取结果一律 `confidence: extracted`，经 AI 独立对拍 + 用户人工签核后才可升 `verified` 进沙盒。
- **CC-BY-SA 数据隔离与 LGPL-3.0 代码许可解耦、保持独立**：换证不改变数据义务。

### 6. CI 强制

`license-scan` 每次 PR 扫描 `pnpm-lock.yaml` / `Cargo.lock` / `requirements.lock`：

- **白名单**：MIT / BSD-2-Clause / BSD-3-Clause / Apache-2.0 / ISC / CC0-1.0 / CC-BY-4.0 / **LGPL-2.1 / LGPL-3.0**。
- **禁止**：AGPL-* / GPL-2.0-only（直接失败）。
- **GPL-3.0 组件**：依选型决策不纳入主链；出现即告警并要求 ADR。
- 同时校验 `lgpl-link-check` 与 `assets/attribution/ASSETS.csv` 覆盖全部入库资产。

## 理由

1. **AGPL 更危险**：网络使用即视为分发，连「独立服务」都可能触发，必须完全不碰（B6）。
2. **隔离 ≠ 降质**：台账 6.2 已确认现有选型（SUNDIALS / SciPy / Cantera / ChemPy / pyequion2 / Reaktoro / RDKit / 3Dmol.js）覆盖全部关键能力。
3. **动态链接是 LGPL 的最宽松路径**：既让 Reaktoro 成为主链组件，又零合规风险，用户还能自行换库版本。
4. **数据 SA 边界可控**：独立仓 + 只取事实 + 独立署名，把义务限制在数据衍生品，不污染主代码。
5. **换证不是合规补丁**：见 ADR-0001 与台账 P4；本 ADR 的义务清单是**主动的合规工程**，不是修漏洞。
