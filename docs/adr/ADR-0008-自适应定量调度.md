# ADR-0008 · SP-1 自适应定量调度（全局最优方案）

- **状态**：**已接受（2026-11-14）** —— 主管依台账 **4.3** 用户授权「我希望追求全局最优，不要拖累进程，请你在此处规划最优方案」产出，不再回来确认；**11.1** 用户认可 §7 噪音/幻觉审计（含 F4 概念 / 库分离修正）
- **依据**：台账 §2.5 SP-1、3.4 / 4.3（C3 销项）、§7.4 F4、6.2（C15 措辞）
- **关联**：ADR-0002（动态求解层）、ADR-0003（前后端常驻 / 表现解耦）、ADR-0006（数值字段）、`design/02`、`design/03`、`design/07`

## 背景与目标

台账 2.3 / 3.4 要求「一切分析必须定量、动态实时求解、追求全局最优」，且服务端定量求解成为**实时主计算层**；4.2 要求 60fps 与定量求解协同。用户 4.3 授权主管产出最优方案，明确兑现五条：

1. **不自适应硬编码阈值**（分类不能靠人为拍 τ）；
2. **把算力给到正在观察的过程**；
3. **确保 60fps 与定量求解协同**；
4. **追求全局最优**；
5. **不拖累进程**。

## 决策：四层解耦架构

### 第 1 层 · 数值自适应层（消灭硬编码阈值）

- 求解步长由 **CVODES 的局部误差估计 + `rtol` / `atol` 容差**自动决定；刚性检测自动在 **BDF ↔ Adams** 间切换。
- 快反应（电离 / 水解 / 酸碱，τ→0）走**代数平衡直接求解**，慢反应走 **ODE 积分**；**分类由数值刚性自动判定，不是人为拍 τ 阈值**。
- 直接兑现「不人为硬编码阈值、实时间隔长短自适应」，并销项 C3（「按时间尺度分类」改为数值刚性自动判定）。
- 对应 schema 字段：`numerics.rtol` / `numerics.atol` / `numerics.stiffness: auto`（ADR-0006）。

### 第 2 层 · 算力调度层（把算力给到正在观察的过程）

引入 **Significance Manager 范式**（概念借鉴），为每个容器 / 反应计算**关注度分数**：

```
significance = w1·视野内 + w2·刚被操作 + w3·有可见现象 + w4·时间轴聚焦
```

| 分数 | 调度行为 |
|---|---|
| 高（焦点内） | 高频、高精度实时求解，`rtol/atol` 收紧，物种分布快照密集 |
| 中 | 常规频率与容差 |
| 低（焦点外） | 降频 / 粗粒度 / **冻结并复用缓存** |

- 总算力按**帧预算（16.7ms）动态配额**，而非固定分层；关注度由客户端观察行为实时上报，服务端据此重排求解队列。
- 兑现「把算力给到正在观察的反应/过程，体验优先」「不拖累进程」。
- 对应 schema 字段：`numerics.significance: auto`（可由服务端覆盖）。

### 第 3 层 · 表现解耦层（60fps 不被求解拖累）

- **WASM 容器内现象渲染按固定 60fps 独立渲染**（ADR-0003）。
- 求解结果以「**物种分布快照 + 时间戳**」异步喂入，中间用**插值 / 外推平滑**；前端显示「计算中…」时现象动画继续。
- **求解耗时与帧率彻底解耦**，重体系不掉帧。兑现「确保 60fps 与定量求解协同」。

### 第 4 层 · 事件唤醒 + 缓存层

- **加料 / 加热 / 改参数 / pH 突变 / 时间轴跳转**等事件立即唤醒相关体系重算。
- **稳态冻结不重复求解**；平衡态结果缓存复用（key = 体系 + 条件哈希 + `ruleset_version`）。
- 呼应既有「热 / 温 / 冷路径」设计，但**废弃其中的本地离线规则包与断网语义**（C8）。

## 验收口径（可量化）

| 项 | 标准 | 对应红线 / 裁决 |
|---|---|---|
| 数值正确性 | **注意力焦点内反应数值零错**（方向、产物、计量、守恒、平衡趋势、pH / 浓度） | 台账 3.3 红线 |
| 帧率 | 恒 ≥ **60fps**，重体系不掉帧 | 4.2 / 4.3 |
| 算力单调性 | 焦点外体系算力占用随关注度**单调下降** | SP-1 |

| 无硬编码阈值 | 代码中不存在人为设定的反应快慢时间阈值 | 4.3 / C3 |

## 合规

- SP-1 数值链为 **BSD-2 / BSD-3 / LGPL-2.1**，全部与 LGPL-3.0 主项目兼容。
- **不引入 AGPL / GPLv2-only**；**GPL-3.0 组件因选型决策不纳入**（C15 措辞，台账 6.2）。
- Reaktoro 按【补正 A】以动态链接 + 可替换形态接入，履行 §6 义务（ADR-0005）。
- Significance Manager 仅为**设计范式概念**，不构成第三方代码依赖，不产生许可证义务（F4）。

## 反面约束

- 不得引入人为的「快 / 中 / 慢反应」固定时间阈值来替代数值刚性自动判定。
- 不得让求解任务占满帧预算导致 60fps 失守。
- 不得把「关注度」做成硬编码白名单；必须由观察行为数据驱动。
- 不得把借鉴的调度范式表述为「已核实的开源库」（F4）。

## 待 M0 验证

1. CVODES 在典型中学体系（中和、弱酸电离、水解、沉淀溶解平衡）上的自适应步长与刚性切换表现。
2. 关注度分数权重 `w1..w4` 的标定（以「焦点内数值零错 + 60fps」为约束调优）。
3. 快照插值 / 外推在慢放热、指示剂突变等场景的视觉平滑度。
4. 稳态冻结与缓存复用的命中率，以及事件唤醒的响应延迟。
