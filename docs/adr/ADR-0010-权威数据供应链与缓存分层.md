# ADR-0010 · 权威数据供应链与缓存分层（权威源物化 / 免计算缓存 / 隔离仓）

> **状态**：已接受（2026-11-16，阶段二补充规划收口）
> **上位依据**：`CHARTER.md` 第 0 / 2 / 3 / 5 / 7 条；[`docs/11-问题与决策台账.md`](../11-问题与决策台账.md) **§9.6**（E1–E16，决策单一事实源）
> **触发**：[`docs/research/05-权威数据源与缓存可行性核验.md`](../research/05-权威数据源与缓存可行性核验.md) 逐库一级来源核实与三组实测；流程见 [`docs/12-阶段二开发流程.md`](../12-阶段二开发流程.md) S6 → S7
> **关系**：本 ADR 是台账 §9.6 E3 / E9 / E11 / E12 触及固定裁决的**生效口径载体**；与 `ADR-0005`（数据隔离）、`ADR-0006`（静态/动态分层）、`ADR-0009`（求解器链）**不冲突**——本 ADR 补齐其「权威数据如何进静态参数层、如何免计算缓存、受限源如何隔离」的实现口径。凡冲突处以本 ADR 与台账 §9.6 为准。
> **纪律**：本 ADR 不产生台账 §9.6 之外的新裁决；实现细节（键结构、物化格式、目录布局）由主管工程判断落地并在此登记。

---

## 一、背景：台账 10.3「权威源」只是机构名，未落到可自托管的供应链

阶段二补充规划前，台账 10.3 把权威源固定为「NIST / CRC / IUPAC / 课标附录 / 开放教材 + AI 对拍 + 用户签核」，但存在三个空白：

| # | 空白 | 实测 / 一级来源证据 |
|---|---|---|
| 1 | 只有机构名，无**具体库 + 端点 + 许可证 + 快照日**，无法离线固化 | 8 个用户示例库 + 主管主动扩展候选池逐库核实（research/05 §三）；多引擎检索严重污染，改走官方原文 |
| 2 | 「反应缓存加速」目标错位 | M0 实测 phreeqpython 单次求解 **0.21ms**（<<16.7ms 帧预算），主引擎无需提速；真实价值在**免计算物化 + 重体系/对拍复算复用 + 数值可复现**（E4） |
| 3 | 外部数据「AS IS」与「数值零错」红线的关系未定义 | NIST/CAMEO 官方均声明不保证准确性；SRD46 SQL 被 NIST 自标「known errors」（台账 §9.6.2） |

用户裁决 E1–E16（台账 §9.6）给出完整口径：全谱系分层覆盖（E1）、外部数据仅作待签核候选池（E2）、改写 10.3 清单（E3）、免计算+可复现分层（E4）等。本 ADR 把这些裁决落为可执行的**五层供应链架构**。

## 二、决策（逐项，均为用户裁决，逐字原文见台账 §9.6）

| 裁决 | 决策内容（生效口径） |
|---|---|
| **E1** | 权威源全谱系分层覆盖：水溶液/常规实验台 + 燃烧爆炸/高温高压/多相气相，各按引擎分工配源（对齐 D2-补） |
| **E2** | 外部数据**一律不直通事实层**；经 AI 独立对拍 + 用户签核 + CI 黄金用例才进静态参数层；禁止把权威库自身权威性当免签理由 |
| **E3** | 改写台账 10.3：机构名清单 → **具体可机读库 + 端点 + 许可证 + 快照日**清单；保留「权威源 + AI 对拍 + 用户签核」流程（走本 ADR + CHARTER 第 7 条） |
| **E4** | 缓存目标从「算得快」改为「**免计算 + 数值可复现**」：物化静态参数层 + 重体系/对拍结果内容寻址缓存 + 扩展 `solve_cache`，不新增中间件 |
| **E5** | CAMEO 只抽「反应基团分类 + 两两相容性判定」事实性结论，独立仓物理分离 + 逐条署来源，不整库复制；赔偿条款与商标法务复核 |
| **E6** | 红线库统一逐库定级：Burcat 永久禁用（JANAF 替代）、NASA CEA 只读参考、WebBook 仅验算引用、ATcT 受限留复跑、Thermochimica/PyThermoCalcDB-NASA 弃用 |
| **E7** | 10.3 保留「不引入商业数据库 / 不引入精度分级」两条，新增四条准入判据（见 §四） |
| **E8** | 物化层 = 版本化 YAML/JSON；缓存 = 内容寻址键（体系+条件+求解器版本+ruleset 版本）；失效由三版本驱动；不引入 Redis 之外中间件 |
| **E9** | K12/课标从内容组织主轴降为**可选检索标签**，主线按「化学体系/玩法/器材」组织（生效口径变更，走本 ADR） |
| **E10** | 数据三类分层：计量/热力学/动力学→事实层（零错签核）；颜色/焰色/外观→表现层元数据（可夸张、标来源）；GHS/安全/危害→事实层安全字段（严谨签核） |
| **E11** | **构建期固化、运行时零依赖**：权威数据构建期离线快照固化（端点/许可/快照日/校验和）随产品分发；PUG-REST/CAMEO 仅内容生产期人工拉取 |
| **E12** | 受限源统一 `data-thirdparty/` 独立公开仓（含 `ord/` `cameo/` 子目录 + 各自 LICENSE），主仓仅 submodule 引用（生效口径变更，走本 ADR） |

## 三、五层供应链架构（E1 / E3 / E8 / E11 落地）

```
① 权威源层（离线、构建期）
   USGS PHREEQC 库族(wateq4f/pitzer) · NIST SRD13 JANAF · SRD17 Kinetics
   · SRD46 稳定常数(标注已知错误) · NIST ASD(SRD78) · ATcT(受限) · CAMEO(隔离)
        │ 构建期人工拉取 + 一级来源核实 + 快照固化(端点/许可/快照日/sha256)
        ▼
② 候选池层（confidence: extracted，不直通）
   每条带 source / confidence / applicability；AS IS 数据一律暂存候选池
        │ AI 独立对拍(解析解/黄金用例) + 用户签核
        ▼
③ 静态参数层（唯一事实源，confidence: verified）
   版本化 YAML/JSON，进 git 可 diff/回滚，复用 content/rules
   schema 三分类：fact(计量/热力学/动力学) / presentation(颜色/外观) / safety(GHS/危害)
        │ 构建期物化 O(1) 查表（免计算，E4）
        ▼
④ 运行时求解层（动态，事实源仍是③的 ruleset）
   phreeqpython(水溶液) / reaktoro-service(多相高温) / Cantera(燃烧) / SciPy LSODA(刚性)
        │ 内容寻址键缓存（体系+条件+solver_ver+ruleset_ver）
        ▼
⑤ 缓存层（复用 solve_cache，零新中间件）
   失效由「数据快照版本 / 求解器版本 / ruleset_version」三者驱动
```

**关键工程发现（实测，research/05 §五）**：
- `phreeqpython` 自带 `phreeqc.dat` 是压力依赖精简版（仅 3 条 log_k），真正物化主源是 `wateq4f_PWN.dat`（749 条）/ `pitzer.dat`（94 条），四库合计 852 条 log_k，带 NIST/minteq/WATEQ4F/SUPCRT 溯源。
- 23 个反应式在库内多版本共存（如 `H2O=H2O` 有 log_k 0 与 1.51）→ **内容寻址键必须带数据源/版本维度**，不能只用反应式名（印证 E8）。
- PubChem PUG-REST 机读 JSON 实测通过（乙醇 C₂H₆O / 46.07），可作构建期离线快照来源；ATcT 403、SRD46 入口 404 如实标受限、留复跑路径。

## 四、准入判据（E7：两条硬约束 + 四条新增）

保留 10.3 原两条硬约束：**不引入商业数据库**、**不引入精度分级**。新增四条准入判据：

| # | 判据 | 门禁落地 |
|---|---|---|
| A | 公共领域 / 宽松许可，可进 LGPL-3.0 主链 | `verify_auth_s2.py` 许可证白名单；禁 Burcat（非商业红线）/ AGPL 主链 |
| B | 可自托管、可机读批量（构建期快照） | 端点实测可达性 + 机读格式解析（auth_endpoints 5/5） |
| C | 带版本 / 快照日 / 可溯源 | 快照四要素（endpoint/license/snapshot_date/sha256）完整性校验 |
| D | 官方声明 AS IS 的须 AI 对拍 + 用户签核 | 候选池 `confidence: extracted` → 签核后才 `verified`（E2） |

## 五、数据三类分层（E10 落地）

| 类别 | 内容 | 红线 | 物化 schema 字段 |
|---|---|---|---|
| **fact** | 计量 / 热力学 / 动力学数值（Ka/Ksp/E°/ΔG/logK/A·n·Ea） | 零错 + AI 对拍 + 签核 + CI 黄金用例 | `confidence: verified` + source + applicability |
| **presentation** | 颜色 / 焰色 / 外观（NIST ASD、PubChem 外观） | 允许视觉夸张，不受零错红线，**仍标来源** | `confidence: presentation` + source |
| **safety** | GHS / 安全 / 危害（驱动「错误操作后果」玩法） | 严谨、带来源、签核 | `confidence: verified` + source + thirdparty_ref（若来自隔离仓） |

## 六、隔离仓与内容组织口径（E12 / E11 / E9 落地）

- **隔离仓**：由台账 10.4「`data-ord/` 独立仓」调整为「`data-thirdparty/` 统一独立仓（含 `ord/` `cameo/` 子目录）」；CC-BY-SA 物理分离立场不变，仅合并载体降运维成本（单仓 + 子目录 + 逐源 LICENSE）。`.gitignore` 以 `data-thirdparty/` 为准，主仓仅 submodule 引用。
- **供应链**：运行时零网络依赖（E11）；`SECURITY.md` 的 PubChem 口径改为「仅构建期、≤5 req/s 走官方批量通道；运行时零网络依赖」。
- **内容组织**：`curriculum` / `knowledge_points` / `textbooks` 从组织主轴降为可选检索标签（E9）；主线按「化学体系/玩法/器材」组织；教学层仍为长线（不改 CHARTER 第 0 条「核心玩法为绝对主体」）。

## 八、后果与风险

| 项 | 说明 |
|---|---|
| 正面 | 权威源从「机构名」落到「可机读供应链」；缓存目标纠错为免计算+可复现；受限源合规隔离；数值零错红线不破 |
| 风险 1 | NIST SRD46 SQL 官方标「known errors」、已停更 → 只作待签核候选，禁止直通事实层 |
| 风险 2 | CAMEO 第三方字段（CAS/DuPont/NFPA/AEGL/ERPG）禁复制 + 赔偿条款 + 商标 → 只抽事实性结论、独立仓、法务复核 |
| 风险 3 | WebBook 留未来收费权、ATcT 403、SRD46 入口 404 → 运行时零网络依赖，保留复跑路径 |
| 风险 4 | 多版本反应式 → 内容寻址键必须带版本维度，否则缓存键冲突（实测已证） |
| 缓解 | 全部通过 `verify_auth_s2.py`（38 断言）+ `verify_m0_s2.py`（M0 归档）双门禁 + CI 全绿才准推送 |

## 九、验收与复验

- `docs/research/05` 报告逐库一级来源事实表 + 三组实测结论 + E1–E16 落点齐全。
- `docs/research/data/s2-auth/` 三组脚本 + JSON 成对可重跑（14/14）+ `verify_auth_s2.py` 全绿。
- `docs.yml` 同时接入 `verify_m0_s2.py` 与 `verify_auth_s2.py`。
- 台账 §9.6 E1–E16 全部固定；本 ADR 与台账 §2.12 10.3 生效口径补注一致。
- 旧口径回归三项：易混淆措辞清零、红线库无正面收录、主链许可证无违规引入（均由 `verify_auth_s2.py` 自动核验）。
