## 背景

需求是「部署在自己的服务器上」「性能最佳」「Win + Linux 双平台兼容」。关键矛盾：

- 定量平衡 / 动力学 / 物种分布求解需要成熟的数值库与算力，且必须成为**实时主计算层**（台账 2.3 / 3.4）；
- 实验台范式下，用户观察的是**容器内的现象**，不是无限画布粒子网格（台账 5.1 / 6.1）；
- 因此「把规则包下载到本地、断网也能玩」既无必要，也会把化学事实层降级为近似。

## 备选

| 方案 | 判断 |
|---|---|
| A. 保留断网可玩 + 客户端 WASM 轻量求解（3.1 选项原文） | 用户【文字】明确否决：「前后端缺一不可，废弃断网可玩标准，不能退而求其次」；且客户端近似求解有违数值零错 |
| B. 全部计算与渲染都在服务端 | 60fps 表现受网络 RTT 拖累，体验差 |
| **C. 前后端常驻 + 服务端定量求解 + 容器内 WASM 表现** ✅ | 事实层严谨、表现层流畅、两者解耦；兑现「前后端缺一不可」 |

## 决策

1. **前后端常驻**：浏览器（Web 端）+ 本地服务器后端**缺一不可**。**正式废弃「断网可玩」标准**（台账 4.2 / C1 销项）。
2. **服务端为唯一事实源**：动态定量求解、物种分布、规则库、参数、存档与时间轴**全在服务端**；客户端不接受越权写入。
3. **WASM 职责收窄为两层**（台账 6.1）：
   - **容器内现象即时渲染**：液体、气泡、沉淀、火焰、飞溅、烟雾等，固定 60fps 独立渲染；
   - **求解加速**：可选的本地数值辅助，结果仍以服务端为准。
   - **废弃**无限画布、落沙网格、Sandspiel 落沙基座与「双视图融合」。
4. **删除整套离线设计**：Service Worker、IndexedDB、离线规则包、PWA 离线、夜间规则包下发、本地 Top-N 规则缓存——**不留死代码**（C8 销项）。
5. **前后端契约**：服务端以「物种分布快照 + 时间戳 + 现象指令」异步喂入 WASM 表现层，中间用插值 / 外推平滑；**求解耗时与帧率彻底解耦**（SP-1 第 3 层，见 ADR-0008）。
6. **Win + Linux 双平台硬约束**（台账 9.1 / C28）：CRLF/LF（`.gitattributes` 强制 LF）、路径大小写统一小写字、卷挂载、端口占用、WSL2 / Docker Desktop 差异须前置设计；M0 增双平台验证项。单机 / 多机 / 公共 Demo 形态**延后到阶段二决策**。
7. **轻量存档**：废弃 Yjs 多人实时协作与复杂存档 diff / 分享（台账 9.4 / C29），改为服务端轻量存档 + 关键快照时间轴回放。

## 理由

1. **零科学性错误**：化学事实层集中在服务端，用成熟求解器实时定量计算，不受客户端算力与近似规则限制。
2. **60fps 与求解协同**：表现层固定帧率独立渲染，求解结果异步喂入，重体系不掉帧（SP-1）。
3. **实验台范式自洽**：用户观察的是容器，WASM 只需渲染容器内现象，不再需要无限画布网格（6.1）。
4. **全局总成本最低**：一套 Web 前端 + 一套服务端，无离线同步、无 CRDT、无双份规则包。
5. **自托管友好**：数据留在自己服务器；双平台兼容让 Windows 用户不被排除在外。

## 影响

- `design/01` 原则 1 重写为「前后端常驻、服务端为事实源」；架构图删除 `IndexedDB` / 本地规则包 / 无限画布。
- `design/05` 删除 Service Worker / IndexedDB / 离线规则包 / Yjs 相关包与目录，增跨平台路径规范与 `.gitattributes`。
- `design/07` REST/WS 契约按「服务端求解 + 快照推送」重写；部署章节增「跨平台兼容」。
- `SECURITY.md` 攻击面按新架构重列（求解器资源隔离、WASM 容器内输入、时间轴快照）。
- `CHARTER` 第 1 条底线改为「前后端缺一不可，废弃断网可玩」。

## 反面约束

- 不得为了「离线也能玩」把化学事实层降级为客户端近似规则（违反数值零错红线）。
- 不得把 Service Worker / IndexedDB / 离线规则包以「预留扩展」名义留在仓库里形成死代码。
- 不得引入需安装的桌面客户端作为主交付形态。
- 不得只验证 Linux 就宣布部署可用；Windows 与 Linux 必须各跑一次最小部署。
